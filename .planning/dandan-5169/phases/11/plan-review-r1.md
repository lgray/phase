## Findings

### F1 (blocking, tag `behavior`): `engine_resolution_choices.rs` scope is over-extended and carries three defective rows

The plan admits the whole file for six producers; only one (the `DigChoice` kept map) is needed by any of the 23 Dandan cards. The other five are out of the charter's literal rule, are not needed, and three are defective:
1. `DiscoverDeclined` / `ResolutionCastRejectedToHand`: origin is Exile (discover.rs:61), so the plan's origin gate returns `None`: the supply is dead code and cannot be made red by a revert leg.
2. `route_kept_card_or_defer`: `player` there is the hit card's controller (the owner), the wrong taker.
3. `route_rest_partition_then(.., taker)`: the signature change forces `effects/ripple.rs:192` and three `dig.rs` call sites that the plan never lists, so the executor would stop-and-return on a compiler error.

Required revision (durable form, not a count): the phase's `engine_resolution_choices.rs` edit is exactly "the `ZoneMoveRequest::effect(..)` map in the `DigChoice` `SelectCards` arm gains `.performed_by(player)` when `kept_zone == Zone::Hand`" (or unconditionally; the seam gates on `to`). Delete the search-partition, Cultivate, Discover, cast-rejected and `route_kept_card_or_defer` rows from 3.4 and from the scope matrix; record the omitted class in the stated-limit paragraph beside the "owner's hand" limit: "no Dandan card reaches a library-to-hand search partition, discover or reveal-until-to-hand; the seam is ready (a producer supplies `.performed_by`), the supply is left to the first card that needs it", with the verdict "dropped, not deferred" in the plan's existing vocabulary. Delete the Cultivate half of V7 (Cultivate is not a Dandan card and its row exercises a dropped producer). The `route_rest_partition_then` signature then stays and `ripple.rs` is not touched. If the orchestrator instead wants the sibling producers in this phase, the plan must (i) add `effects/ripple.rs` and name the `dig.rs` `route_rest_partition(` sites, (ii) change `route_kept_card_or_defer` to carry an acting player, (iii) drop the two Exile-origin rows, and (iv) say why a card-less producer is in scope; that is a charter-scope decision this review does not make. The recommended path is the narrow one.

### F3 (non-blocking, tag `text`): the `debug_assert!(receiver.is_none())` in the raw branch is reachable

3.3 says the origin gate makes it unreachable. It is not: `move_to_zone_with_entry_flags` rewrites `to` to `Zone::Command` for an Attraction card (`redirect_attraction_to_command`, zones.rs about line 1352) after the event's `to == Hand` was accepted by the seam. A Library-to-Hand receiver then reaches the raw branch and the `debug_assert!` panics in a debug build. Replacement text: "The receiver is applied only when the final `to` (after the CR 717.6 Attraction redirect) is `Zone::Hand`: `let receiver = receiver.filter(|_| to == Zone::Hand);` immediately after the redirect, with no `debug_assert!`." Add a SEAM row case or a sentence to V9 that an Attraction redirect leaves the card unrebound (it is also a paired reach-guard for the filter).

### F4 (non-blocking, tag `text`): V6 fixture must give P0 an Island

Dandân: "When you control no Islands, sacrifice this creature." After P0's Control Magic resolves, P0 controls Dandân; if P0 has no Island the state trigger fires and the row's later "Dandân is in P1's hand" can be decided by a sacrifice. Control Magic costs {2}{U}{U}, so P0 must tap Islands in any case; add to V6: "P0's Control Magic is paid from Islands P0 keeps on the battlefield (Dandân's trigger must not fire), and P0's Control Magic is a P0-owned card placed in P0's hand with `owner == P0`". Also say how P1 reaches {U}{U} for Dandân (two Islands, as written) and still pays {1}{U} for Unsubstantiate (the plan lists no extra mana): "P1 controls four Islands".
