## 3. Design

### 3.1 The defect at PHASE_BASE (class statement)

In a shared-library format the 8-card "move, shuffle, draw" wheel class (section 4) resolves as one complete wheel per seat: seat 0 moves its hand and the graveyard cards it owns, shuffles the pile, draws seven (a Phase 14 dealer is not reached because the `Draw` is local, not a clause head); only then does seat 1 move its hand into the pile, shuffle again and draw. The brief states the consequence: "P1's hand is shuffled in after P0 has drawn". Settled decision 2 requires every hand and the shared graveyard to be shuffled into the pile once, then 14 cards dealt one at a time, active player first.

### 3.2 The transform (one function, `effects/mod.rs`)

New private `fn shared_library_wheel_split(state: &GameState, ability: &ResolvedAbility, scope: &PlayerFilter) -> Option<ResolvedAbility>` beside `split_player_scope_chain`. It returns the chain with two links re-tagged, or `None` (the caller keeps `ability` unchanged). All must hold:

1. `state.format_config.format.shared_zones().library == ZoneScope::Shared` (the axis Phase 14 reads; every other format returns `None` and keeps today's chain, so the pinned per-player wheel is byte-identical).
2. The chain from `ability` is: one or more **pile-return moves**, then a shuffle node, then a draw node, each next node linked `ContinuationStep`. A pile-return move is a node with `!optional`, no `condition`, and effect `ChangeZoneAll { origin: Some(_), destination: Zone::Library, target: ScopedPlayer, library_shuffle: TerminalShuffle, .. }`. The shuffle node is `Effect::Shuffle { target: ScopedPlayer }` with `!optional`, no `condition`, no `player_scope`. The draw node is `Effect::Draw { count: QuantityExpr::Fixed { .. }, target: ScopedPlayer }` with `!optional`, no `condition`, **`player_scope == Some(scope)`** (the parser's own stamp on a clause that is a separate scoped instruction; a Draw with no own scope is not this shape).
3. The root's `player_scope` is `Some(scope)` (the driver's `driver_scope`).

Rewrite: clone `ability`; set `sub_link = SequentialSibling` on the shuffle node and on the draw node. Nothing else changes (the draw keeps its own `player_scope`, its `EndTheTurn` or other tail stays its sub).

Why this is the whole split, with no predicate change: `detach_after_player_scope_local_chain` keeps a next node local only when `next.sub_link == ContinuationStep && is_player_scope_local_continuation(..)`. With the shuffle re-tagged, the head (`ChangeZoneAll` moves) stays per-seat and the shuffle is returned as `after_scope`, whose remaining links are the re-tagged draw and the original tail. The existing driver then does exactly the wanted order with its existing machinery: (a) per-seat moves in APNAP order (hand, then the graveyard cards that seat owns; the scan is by `object.zone` and `owner`, so the shared graveyard is emptied across the two seats' passes: UNESTABLISHED P3); (b) `after_scope` = the shuffle node, resolved ONCE as an unscoped node, its `ScopedPlayer` target unbound so it resolves to `ability.controller` (read: `resolve_player_for_context_ref`'s `ScopedPlayer` arm), whose library is the pile; (c) its re-tagged `SequentialSibling` draw sub re-enters the driver on its own `player_scope`, where Phase 14's gate engages the dealer with `seats` built from `matching_players`; (d) the draw's own tail (`EndTheTurn`, `SequentialSibling`, `IsYourTurn`) is detached by that driver and runs after the dealer completes (or after a park, as Phase 14's `Parked` path inserts it). A pause inside the move passes parks the remaining seats and the whole `after_scope` through the driver's existing continuation path (unchanged).

Call site: in the `driver_scope` block of `resolve_chain_body`, immediately before `scoped_library_search::has_only_detachable_shuffle_tail(ability)` / `split_player_scope_chain`: `let wheel = shared_library_wheel_split(state, ability, scope); let ability = wheel.as_ref().unwrap_or(ability);`. The driver's later uses of `ability` (the discard-batch `outer`, `publish_player_scope_clause_results`, the continuation builders) then all see the one rewritten chain, so there is no second view of it. `scope` still borrows from the original ability, which outlives the block.

Reuse, not duplication: the pile-return move pattern already appears twice in `is_player_scope_local_continuation`'s `is_scoped_library_shuffle_chain` arms. Extract `fn is_scoped_pile_return(effect: &Effect) -> bool` (the `ChangeZoneAll { origin: Some(_), destination: Library, target: ScopedPlayer, library_shuffle: TerminalShuffle }` pattern) and use it in the new function and in those two arms (`(pile_return, pile_return)` and `(pile_return, Shuffle{ScopedPlayer})`); the remaining arms of that `matches!` are untouched. Behavior-identical by construction; the existing unit rows (`hand_to_library_shuffle_local_continuation_requires_exact_scoped_pair`, the #6957 rows) are the guard. This is the charter's `is_player_scope_local_continuation` edit, scoped to the extraction.

### 3.3 Interaction with Phase 14's gate (what must hold at PHASE_BASE)

The `Draw` clause reaches Phase 14's layer-1 intercept as `Draw{Fixed 7, ScopedPlayer}` with `player_scope All` and (after `split_player_scope_chain`) its tail detached. Phase 14's conjuncts, each read against `phases/14/plan.md` 3.2/3.4 and checked by the executor at PHASE_BASE: `seats.len() >= 2`; `starting_with` None; `shared_zones().library == Shared`; `!count.peel_up_to().1` (Fixed); `has_no_resolution_riders(seat ability)` (the seat is the split `scoped_template`, whose `sub_ability` is None because the tail was detached; the `detached_remainder` marker is `NoProducer` for an `EndTheTurn` tail: UNESTABLISHED P7); `resolve_player_for_context_ref(ScopedPlayer) == seat` (the driver's `set_scoped_player_recursive`, as Phase 14's `bind_scoped_seat` does); `!after_scope_needs_linked_exile && !next_sub_needs_tracked_set(ability)`. `next_sub_needs_tracked_set` for the Draw clause inspects `EndTheTurn` (no tracked-set consumer; `player_filter_references_tracked_set(All)` is false; read of `node_or_branch_references_tracked_set`), and for Timetwister there is no sub, so **Phase 14's "Phase 15 widens this" is not needed**: the clause this phase hands the dealer is a bare scoped `Draw` with a non-consuming tail. If Phase 14's landed gate nevertheless refuses it, the Draw clause falls back to the sequential per-seat fan-out of the draw ALONE (still after all moves and the one shuffle: ordering and shuffle count remain correct; only the interleave is lost) and the W1/W1b interleave assertions go red: a stop-and-return naming the refusing conjunct, never a gate edit in this phase.

### 3.4 What is deliberately not in the class (measured boundary)

The transform accepts only a `Fixed` draw whose recipient is `ScopedPlayer`. Corpus census (python over `card-data.json`, section 7): 8 cards match all of section 3.2: Day's Undoing, Timetwister, Echo of Eons, Time Reversal, Emergency Powers, Game Plan, Arzakon (-7), Immortus, Master of Eternity (power-up). Excluded, each with its reason:
- `EventContextAmount` draws with a `ScopedPlayer` recipient (The Great Aurora): the count reads the per-player table `last_effect_counts_by_player`, and a detached `Shuffle` is a non-producer that clears that table (`install_previous_effect_counts_by_player`'s `None` arm), so detaching the shuffle would zero the count. They keep today's chain.
- Winds of Change, Molten Psyche, Whirlpool Warrior (`Draw` recipient `Controller`, `EventContextAmount`): already a native detached scoped `Draw` (they do not match the pair rules), so they reach Phase 14's dealer unchanged, with one shuffle per seat. Their shuffle count (two, not one) is not asserted anywhere; decision 2 names Day's Undoing, and one shuffle per seat is correct for the stock format.
- Step Between Worlds ("may" shape: root `optional`, Draw gated on `OptionalEffectPerformed`): not a plain wheel; keeps today's chain.
These are excluded by the shape gate (hostile unit rows U2), not deferred work: no Dandan card is in them and the charter's deferral list is empty.

**Extension vs Creation.** Extends the existing driver (one pre-split transform and one call line) and the existing predicate (helper extraction). Creates no parallel resolution path: the move phase, the park/continuation path, the shuffle and the dealer are all existing code.

**Nom Compliance.** N/A: no file under `parser/` changes.

**Variant Discoverability.** Section 1: no variant added.

**Identity / Provenance Contract.** (a) *The single shuffle's actor*: source phrase "shuffles ... into their library"; authority `PlayerId` = `ability.controller` of the detached shuffle node (the `ScopedPlayer` target is unbound outside a seat's iteration and resolves to the controller by `resolve_player_for_context_ref`), bound when the tail resolves, live; consumer `library::resolve_and_apply_library_shuffle`, which shuffles `library_of(controller)`, the one pile for every seat (Phase 6); no invalidation. The one `PlayerPerformedAction { ShuffledLibrary }` event therefore names the controller (the active player for a sorcery). The controller of a sorcery is the active player; the active player is the dealing anchor, not the shuffle actor, so the two never need to agree. ## 6. Reference Readings
