## Findings

### F1 (text, blocking) V16 leg (1) expected order contradicts 3.3 and the clamp
Old string: "the returned delivery order equals the order that leaves the first-chosen card above the second at index 2 and 3 of the pile (derived by hand from the clamp, `n - 1 = 2` against pile length 10; an empty-library read returns the reversed order)".
Derivation from `replay_effect_zone_library_placement`: placement order for `NthFromTop` is chosen order `[c1, c2]`; c1 inserts at index 2, c2 inserts at index 2, giving `[.., c2, c1, ..]` (second chosen at index 2, first at 3; the plan's own 3.3 says "the second lands above the first"). `non_library` = `[c2, c1]`, reversed, so the function returns `[c1, c2]`; the empty-library read gives c1@0, c2@1, returns `[c2, c1]`.
Replacement: "the returned delivery order is `[c1, c2]` (pile of 10: replay leaves c2 at index 2 and c1 at index 3, `non_library = [c2, c1]`, reversed); an empty-library read returns `[c2, c1]`."

### F2 (text, blocking) V16 revert claims are not discriminating as written, and one 3.3 claim is false
(a) 3.3 "For `reposition_library_origins_after_batch_delivery` an empty raw read also drops every library-origin card from `desired`, so none is repositioned" is false: `library_placed` is every chosen card with `zone == Library`, which includes the library-origin cards, so the replay inserts them into the empty list at clamp positions and they are repositioned to wrong indices. Same false claim in V16 leg (3) "an empty read repositions nothing". Replace both with "an empty raw read inserts the placed cards into an empty list and repositions the library-origin cards to wrong indices".
(b) V16 "Revert either read to the raw owner lookup: legs (1) and (3) fail": after grouping by storage seat the visited `holder` is the canonical seat, whose raw container is the pile, so reverting `state.library_of(holder)` to `players.find(id == holder).library` is a no-op and no leg fails. The read conversion is subsumed by the grouping and is not separately discriminable. Replacement: "Mutation M1: restore the pre-amendment code (group by card owner, raw read of the owner's container): legs (1), (2) and (3) fail. The `library_of(holder)` swap alone is not separately discriminable once grouping is by storage seat and is kept for accessor consistency." Drop the "revert either read / revert grouping" split.
(c) Leg (3) fixes no chosen order, delivered card's owner or pile position, so "pile order equals the independently derived selection order" cannot fail by construction for every staging (with `[p1c, p0c, d]` the old code reverses p0c/p1c; with other orders it can coincide). Add: chosen order `[p1c, p0c, d]`, `d` already in the pile after delivery (zone Library, at the top as delivery leaves it), derived expectation `[p1c, p0c, d, ..]`, and state that the P0 pass of the old code leaves `[p0c, p1c, ..]`.
