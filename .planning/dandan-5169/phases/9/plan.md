## 4. Design

### 4.1 Mechanism

One mechanism, the Phase 8 shapes: S (`state.library_of(seat)` / `graveyard_of(seat)`), S-guard (the existing absent-seat arm decides presence; only the container read changes, keyed by the looked-up player's own id, because the accessor panics on an unknown seat where `get`/`find` returned `None`), F (storage-identity fold stays raw and carries a pin test). No type, helper, enum or field is added.

### 4.2 Owner-coupled gates next to swapped reads (read at HEAD; behavior decided here)

- `candidates.rs` graveyard loops and `activation_block_reasons`' graveyard loop keep `obj.owner == player` after the swap. CR 602.2 + CR 108.4: a card in a graveyard has no controller and its owner activates it; CR 404.1 puts a card in its owner's graveyard. Under the shared pile the swapped read lets the non-canonical seat enumerate the pile and the unchanged gate admits the seat's own cards, exactly Phase 8's ruling for the `casting.rs` graveyard gates. Which seat may activate an other-owned pile card is a rules decision this phase does not take: `DEFERRED(phase 11)` (Phase 11 owns the owner rebind). No row asserts the other-owned case; every row's cards are owned by the acting seat.
- `card_name_choice_candidates` pushes names, not identities, and has no owner gate.
- `certify_instructed_opponent_library_departure` and `without_certified_departure` key the certified departure by CARD OWNER (`per_victim.entry(prior_obj.owner)`, and the caster exclusion is `owner != caster`) while `library_delta` is keyed by seat. After the `snapshot` swap `library_delta` for both seats of a Dandan state equals the pile's delta, so a pile mill by P1 of a P0-owned card shows a decline on P1 (the caster's own library, a real loss axis per the function's own CR 121.4 / 104.3c reading) that the owner-keyed certificate does not add back; the certificate then fails closed (the bound stays narrowed by the caster's own pile). Verdict: this is an owner-keyed gate, not a container read, so it is outside the sweep class; it is NOT edited, and the plan claims no end-to-end loop-analysis behavior for Dandan (UNESTABLISHED, section 8). The sole reach is a detected repeating cycle; the 23 names contain two one-shot mills and no free recursion (section 1), so they reach no pile-depleting cycle. After the `snapshot` swap `library_delta` is equal on both seats, so `loop_check::classify_win_kind`'s "library loss on a seat other than the controller" test (`n < 0 && *pid != controller`) reads any pile-depleting cycle as `WinKind::Decking`, and the second-loss-path firewall also trips; at base the same misclassification already occurs for a P1 controller (only P0's container shrinks). Not edited and not claimed (outside the container-read class; no card in the list reaches it).

### 4.3 determinize.rs, a swap with a deferred consequence and a closed owner-filter residual

`unknown_slots(state, opponent, known)` returns the opponent's hand then `player.library` ids filtered to `known` absent, non-token, `obj.owner == opponent`; `determinize_opponents` resamples those slots from `deck_knowledge::unknown_hidden_pool(&sim, opponent, ..)`, which `find`s the pool by `pool.player == player` and returns empty when none exists (read). Measured by reading, three facts:

- Under Phase 6 canonical storage Dandan has one pool (the canonical seat's), so for `opponent` = the non-canonical seat the pool is empty and the loop `continue`s before using `slots`; for `opponent` = the canonical seat the raw read already is the pile. The read swap is therefore unobservable end to end until Phase 17 converts the pool lookup to the resolver (this path already resamples the pile when the AI is the non-canonical seat; that is pre-existing, correct because CR 401.2 hides the pile from both seats, not a leak and not a double count: slot ids are distinct objects and 2-seat Dandan has one opponent).
- When Phase 17 does, the pile is treated as unknown to the AI instead of leaking its real order. The module's documented invariant ("the AI player's own hand/library are never resampled", with `card_name_choice_candidates` named as a reader of those own zones) conflicts with a shared pile; that conflict, and `card_name_choice_candidates` for the non-canonical AI seat reading the determinized pile's names per sample, are `DEFERRED(phase 17)`.
- `unknown_slots` already consults what the AI knows: its `known` argument is `pinned_known_ids` (revealed and public-revealed cards, the AI's own private looks, and `viewer_knows_card_identity` facts; CR 701.20a / CR 701.20e as the module cites them), and `unknown_hidden_pool` subtracts the same set. No new knowledge helper is needed.

**Edit (swap, S).** Replace `player.library.iter()` by `state.library_of(opponent).iter()`; the `players[opponent.0]` hand read stays.

**Edit (owner-filter residual F2, closed here by orchestrator ruling).** The `obj.owner == opponent` filter is a per-seat-storage assumption: with one pile per game (CR 400.1 as modified by Phase 6) the opponent's hidden library cards are everything in `library_of(opponent)`, whichever seat owns each card; CR 401.2 hides the order and identity of a library from every player and CR 401.3 makes only its size public, so ownership of a library card says nothing about what the AI knows. What the AI legitimately knows is carried by `known`, and tokens are never library cards to resample. The selection becomes: hand slots = `players[opponent].hand` with `known` absent, non-token, `owner == opponent` (hand storage is per seat and a borrowed card in a hand has a public identity, unchanged); library slots = `library_of(opponent)` with `known` absent and non-token, no owner test. In a non-shared format a library only ever holds its seat's own cards (CR 401.1 and CR 400.3 via the zone-routing of `add_to_zone`), so the library selection is the identity there. Phase 17 consumes this: its `deck_knowledge.rs` owner-filter drops and pool resolution rely on `unknown_slots` already returning the pile; `determinize.rs` needs no further Phase 17 edit for the slot selection (the pool lookup, pool-versus-slot count reconciliation across two decks, and the own-zones invariant stay Phase 17's, as above). `zip` truncation already tolerates a pool smaller than the slot set.

Annotation: `CR 401.2` and `CR 401.3` (grepped, 2001 and 2003) on the library-slot comment; nothing else.

### 4.4 Storage-identity sites and their pins (F)

The charter: "Storage-identity reads stay raw when a per-seat accessor would hash the shared pile twice or skip it." Each F site keeps its code and gets a pin test (section 6, V3, V4, V9). Pin design: for the hashes, two states with identical stored containers (pile in the canonical container, the other container empty) that differ only in `format_config.format` (`Standard`-config versus `Dandan`) must hash equal; a swap to per-seat accessors makes the Dandan hash fold the pile twice and fails the equality. Paired reach-guards: a change of the pile's content or order changes the hash (so the hash does read the pile), and a change confined to the pile's graveyard changes it likewise. For the C1b residual (a pairwise equality whose verdict a swap cannot change on a valid state) the discriminating row is a hostile fixture: a stray id in the NON-canonical stored container of `current` only (a state no engine path produces; constructible only by a raw write under `test-support`, which is the reason it is the one way to observe raw versus accessor): the raw fold refuses (`None`), a swap reads the pile for both seats and would certify. The valid-state rows around it are reach-guards, labelled as such.
