## 4. Design

### 4.1 Site classes (one mechanism, five shapes)

| Class | Rule | Why |
|---|---|---|
| S | a single-seat read `X.library`/`X.graveyard` becomes `state.library_of(seat)` / `state.graveyard_of(seat)` | the accessor is the one authority for "seat's pile" |
| S-guard | where the site has an explicit absent-seat arm (`ok_or(PlayerNotFound)`, `get(..).is_some_and`, `find(..)?`), the existing lookup that decides presence stays; only the container read changes, keyed by the looked-up player's own id: `.map(\|p\| state.graveyard_of(p.id)..)` | Phase 6's accessor panics on an unknown seat; Phase 6's own `select_cards_to_draw` keeps the same guard, so behavior on a bad id is unchanged |
| L | an iteration over "the other seats' cards" visits each DISTINCT storage seat once (dedup of `state.players` by `zone_storage_seat(zone, p.id)`), reads it through the accessor, and keeps the per-card predicate `obj.owner != player` (the pass's stated meaning, "someone else's card") | after a bare swap both callers would list a pile card twice (one visit per seat); an exclusion of seats sharing the caller's storage would drop a case HEAD finds (caller P1, P0-owned pile card with a grant for P1: HEAD lists it once). Owner-keyed dedup is the identity on a non-shared format (each seat is its own storage seat and every card there is owned by that seat, so `owner != player` holds exactly for the other seats' cards) |
| Q | the stateless `candidate_player_scalar(p: &Player, ..)` `GraveyardSize` arm moves into `candidate_player_scalar_with_state` (which already holds `state` for `LifeTotal`) and reads `state.graveyard_of(candidate.id)` | a `&Player` cannot reach the storage authority; the sibling exists for exactly this |
| W | the discarded-clone prune in `engine.rs::normalize_recast_frame` removes ids through `graveyard_of_mut` / `library_of_mut`; the hand prune keeps its owner-keyed lookup | the ids sit in the pile holder's container |
| R | `choose_from_zone.rs::object_ids_in_player_zone` and `restrictions.rs::player_zone_ids` keep their shape; their Library and Graveyard arms call the accessors | see 4.4 (interpretation of "fold") |
| F | all-seats flat loops stay raw | under canonical storage they already return the pile once; per-seat routing would duplicate it N times (brief, S2 "Read sweep") |
| D | deferred scoped-player arms stay raw | charter: `DEFERRED(phase 10)` |

The five shapes S, L, Q, W, R are the same mechanism: route a (seat, zone) container access through the storage authority. No new type, enum, helper or field is added.

### 4.3 Owner-coupled gates next to swapped reads (read at HEAD; behavior decided here)

- `morph.rs::top_library_object` finds the top object by `obj.owner == player && obj.zone == Library && library.front() == Some(&obj.id)`, a redundant re-derivation of the id it already holds. In a non-shared format the top card of a library is always owned by that library's seat (CR 400.3), so the owner clause is vacuous there; under a shared pile it rejects a card owned by the other seat ("Top card object not found"). The fix keeps the id obtained from `library_of(player).front()` and checks it exists in `state.objects`; the owner clause is dropped. Its consumers are `effects/manifest.rs`, `effects/cloak.rs` and `morph::manifest` (CR 701.40a manifest, CR 701.58a cloak; CR 702.37 morph is not this path). Class: same mechanism (a read-axis coupling to the zone holder), required for the manifest-from-library class (Soul Summons) and manifest dread (Ethrimik) from either seat; annotate CR 701.40a + CR 701.58a + CR 400.3.
- **Consequence of the owner-clause drop, stated:** P1's manifest of a P0-owned pile top now succeeds; `manifest.rs` with no `enters_under` keeps the card under its library owner's control, so the manifested card enters under P0's control while CR 110.2a gives the putting player (P1) control. That controller leg is dropped from this phase with the verdict "no Dandan card reaches it" (section 0, measured over the 23 names: no library-to-battlefield effect). Rows V4g, V4h and V8d are pile-side only and assert no controller. The Dandan decklist is exactly these 23 cards (brief, "Decklist"), so no other card enters a Dandan game.
- `casting.rs::spell_objects_available_to_cast`, `::castable_from_current_zone`, `::graveyard_permission_sources` carry `obj.owner != player` / `== player` gates on graveyard-cast permissions. Left unchanged: Phase 11's rationale is that no Dandan card casts or plays from the shared graveyard directly, and which seat may cast an other-owned pile card is a rules decision this phase does not take. The swapped read makes the non-canonical seat enumerate the pile; the unchanged gate then admits the seat's own cards. No row asserts the other-owned case (it is `DEFERRED(phase 11)`).
- `choose_card.rs` (`obj.owner == ability.controller`, Hand arm) and `replacement.rs` token-owner scope: not about the swapped zones; unchanged.

### 4.5 Clash end fix and boundary notes

- **`clash.rs::top_card_of_library` is fixed in this phase.** It read `.library.last()`, while the engine's top is index 0 (`draw.rs` and `mill.rs` take `iter().take(n)`, `zones.rs` appends the bottom with `push_back`, `scenario.rs` documents `library[0]` as the top, `morph.rs` and the top-of-library permission reads use `front()`), and CR 701.30a says a clashing player reveals the TOP card (`grep -n "^701.30a" docs/MagicCompRules.txt`). So every clash reveals the bottom card. 27 supported cards parse to `Clash` (python walk over `card-data.json`/`coverage-data.json`; examples Oaken Brawler, Fire Juggler, Pulling Teeth, Scattering Stroke, Whirlpool Whelm); none of the 23 Dandan names is among them (set intersection with `brief/scripts/names.txt` is empty), so the defect is live in every format and outside the Dandan flow. The sweep must rewrite this exact read for the storage authority, so it is rewritten as `state.library_of(player).front()` behind the existing `players.iter().find(..)?` absent-seat guard; leaving a known-wrong end under a new accessor would be a knowing defect in a file this phase owns. The CR 701.30c placement (`ClashCardPlacement` answered by `move_to_library_position`) is Phase 6's code and unchanged. Rows: V15a (defect, Standard, red at base because the bottom is read) and V15b (seat read, Dandan), section 6; the existing `clash` tests in `effects/mod.rs` set no library and do not pin an end (read).
- `engine_resolution_choices.rs::effect_zone_non_library_delivery_order` and `::reposition_library_origins_after_batch_delivery`: Phase 6 owns these two reads (orchestrator ruling; Phase 6 plan amended). This phase touches no line of that file; the dependency is stated in the header and checked at step 0 and by V13.
