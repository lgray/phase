## 4. Design

### 4.1 Site classes (one mechanism, five shapes)

| Class | Rule | Why |
|---|---|---|
| S | a single-seat read `X.library`/`X.graveyard` becomes `state.library_of(seat)` / `state.graveyard_of(seat)` | the accessor is the one authority for "seat's pile" |
| S-guard | where the site has an explicit absent-seat arm (`ok_or(PlayerNotFound)`, `get(..).is_some_and`, `find(..)?`), the existing lookup that decides presence stays; only the container read changes, keyed by the looked-up player's own id: `.map(\|p\| state.graveyard_of(p.id)..)` | Phase 6's accessor panics on an unknown seat; Phase 6's own `select_cards_to_draw` keeps the same guard, so behavior on a bad id is unchanged |
| L | an iteration over "the other seats" excludes seats that share the caller's storage: `zone_storage_seat(zone, other) != zone_storage_seat(zone, caller)`, read through the accessor | a shared pile is never "someone else's" graveyard; without the exclusion the non-canonical caller lists the pile twice |
| Q | the stateless `candidate_player_scalar(p: &Player, ..)` `GraveyardSize` arm moves into `candidate_player_scalar_with_state` (which already holds `state` for `LifeTotal`) and reads `state.graveyard_of(candidate.id)` | a `&Player` cannot reach the storage authority; the sibling exists for exactly this |
| W | the discarded-clone prune in `engine.rs::normalize_recast_frame` removes ids through `graveyard_of_mut` / `library_of_mut`; the hand prune keeps its owner-keyed lookup | the ids sit in the pile holder's container |
| R | `choose_from_zone.rs::object_ids_in_player_zone` and `restrictions.rs::player_zone_ids` keep their shape; their Library and Graveyard arms call the accessors | see 4.4 (interpretation of "fold") |
| F | all-seats flat loops stay raw | under canonical storage they already return the pile once; per-seat routing would duplicate it N times (brief, S2 "Read sweep") |
| D | deferred scoped-player arms stay raw | charter: `DEFERRED(phase 10)` |

The five shapes S, L, Q, W, R are the same mechanism: route a (seat, zone) container access through the storage authority. No new type, enum, helper or field is added.

### 4.3 Owner-coupled gates next to swapped reads (read at HEAD; behavior decided here)

- `morph.rs::top_library_object` finds the top object by `obj.owner == player && obj.zone == Library && library.front() == Some(&obj.id)`, a redundant re-derivation of the id it already holds. In a non-shared format the top card of a library is always owned by that library's seat (CR 400.3), so the owner clause is vacuous there; under a shared pile it rejects a card owned by the other seat ("Top card object not found"). The fix keeps the id obtained from `library_of(player).front()` and checks it exists in `state.objects`; the owner clause is dropped. Class: same mechanism (a read-axis coupling to the zone holder), required for Soul Summons / Whisperwood Elemental class from either seat.
- `casting.rs::spell_objects_available_to_cast`, `::castable_from_current_zone`, `::graveyard_permission_sources` carry `obj.owner != player` / `== player` gates on graveyard-cast permissions. Left unchanged: Phase 11's rationale is that no Dandan card casts or plays from the shared graveyard directly, and which seat may cast an other-owned pile card is a rules decision this phase does not take. The swapped read makes the non-canonical seat enumerate the pile; the unchanged gate then admits the seat's own cards. No row asserts the other-owned case (it is `DEFERRED(phase 11)`).
- `choose_card.rs` (`obj.owner == ability.controller`, Hand arm) and `replacement.rs` token-owner scope: not about the swapped zones; unchanged.

## 6. Verification matrix

**Method.** One new file `crates/engine/tests/integration/dandan_read_sweep.rs` (+ one `mod` line). Fixture: a Dandan `GameState` booted through Phase 6's loader or built by `GameScenario::new_with_format(FormatConfig::dandan(), 2, seed)`; the pile lives on the canonical seat P0 (`canonical_seat()`); the acting seat is P1 (non-canonical, empty container). Assertions are pile-side (which cards leave or enter the shared library, graveyard, exile, battlefield); the receiving hand of a drawn or dug card is `DEFERRED(phase 11)`. Instants are cast by P1 holding priority; sorceries make P1 the active player (UNESTABLISHED how `GameScenario` sets this; the executor uses `GameRunner::from_state` with `waiting_for = Priority { player: P1 }` as Phase 6's V5 does).

**Red/green protocol (revert-failing without a compile per file).** (1) Add the file at PHASE_BASE, run it: every M-row for a swept read is red (the non-canonical seat reads its empty container). (2) Apply the swaps by group, each group green. (3) Rows whose flow crosses two or more swept files are listed in the multi-file table; for those the executor additionally reintroduces ONE file's raw read at a time, shows that row red, restores it. Rows that cross a single swept file are attributed to it by the base-red run plus the reach-guard.

**Template applied to every row (named once).** (a) acting seat P1 over the pile: red at base; (b) paired positive: the same flow from P0 is green at base (instrument fires); (c) paired non-shared: the same flow in a Standard state reads the seat's own library/graveyard, unchanged; (d) the empty-pile path where the handler has one (no panic, no spurious event). A bare negative is always paired with (b).
