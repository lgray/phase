## 2. Pattern Coverage (assessed against the charter's class attribution)

Class: every format whose `shared_zones().library` is `ZoneScope::Shared` runs the CR 103.5 simultaneous declare round, and every pregame card distribution (opening deal, round redraws, Serum Powder's redraw) goes through one deal primitive that reads the format's `DealOrder`. Dandan is the only such format today; the two axes are the extension point, so a future shared-library format (or a `Custom(_)` one, once a custom-format source can express shared zones) inherits the round and its deal order with no code change. The dealer's ordering primitive (`deal_sequence`) is also the one Phases 14 and 15 consume for in-game simultaneous draws and Day's Undoing, so the class is wider than the round. Non-shared formats are the identity case (section 3.1).

## 3. Design

### 3.1 Gate: the round is a function of the shared-library axis, the dealing order a function of the deal-order axis

Measured: `GameFormat::shared_zones()` (`types/format.rs`) returns `SharedZones { library: ZoneScope, graveyard: ZoneScope }`; `GameFormat::deal_order()` returns `DealOrder::{PlayerByPlayer, Interleaved}` (Dandan `Interleaved`); `grep -rn 'deal_order\|DealOrder' crates` outside `types/format.rs` hits only `tests/integration/format_axis_census.rs`, so the deal-order axis has **no runtime consumer at HEAD** and this phase is its first.

Two private-to-`mulligan.rs` readings, one per axis (each its own CR rule, no cross-rule unification):

```rust
/// CR 103.5: when a declared mulligan is carried out.
enum MulliganTiming { Immediate, Simultaneous }

fn mulligan_timing(state: &GameState) -> MulliganTiming {
    match state.format_config.format.shared_zones().library {
        ZoneScope::Shared => MulliganTiming::Simultaneous,
        ZoneScope::PerPlayer => MulliganTiming::Immediate,
    }
}
```

Why the round is gated on the library axis and not run for every format: CR 103.5 makes the redraws simultaneous, and with a library per player that simultaneity is unobservable (no card moves between seats, the other seat never sees the new hand). Only a shared pile makes the order of returning, shuffling and dealing observable (which seat's cards land where, the deal order). The brief says the same ("The round is observable only on a shared pile, so gate it on the shared-zone axis"). The `Immediate` arm is today's eager code, byte for byte.

### 3.2 The declaration carrier: `WaitingFor::MulliganDecision.declared`, not an entry sub-phase

New struct in `types/game_state.rs` beside `MulliganDecisionEntry`:

```rust
/// CR 103.5: a mulligan this player has declared and that is carried out once every player has declared.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct MulliganDeclaration {
    pub player: PlayerId,
    /// Mulligans taken before this declaration (the redraw makes it one more).
    pub mulligan_count: u8,
}
```

and one new field on `WaitingFor::MulliganDecision`: `#[serde(default, skip_serializing_if = "Vec::is_empty")] declared: Vec<MulliganDeclaration>`. Semantics: `pending` stays "the players who owe an action" (`Declare` or `BottomCards`); `declared` is "the players whose mulligan is recorded and waiting for the round to close". A player is in exactly one of the two lists, or in neither once they kept.

Why not a third `MulliganDecisionPhase` variant (the charter's wording, "folded into `MulliganDecisionPhase`", is for FreeReveal availability, Phase 13) or an entry field: measured, a declared entry left inside `pending` is mis-read by three consumers that treat `pending` membership as "owes an action":
- `WaitingFor::acting_authority` (`types/game_state.rs`) builds `Simultaneous(pending.iter().map(|e| e.player))` in an arm its doc comment restricts to one bare constructor call; a phase filter there is the guard-shaped condition the census (`waiting_for_actor_authority_census.rs`, A8) exists to refuse.
- `ai_support/candidates.rs` emits Keep/Mulligan/Powder candidates for every `pending` entry in `Declare`.
- `client/src/game/controllers/aiController.ts::aiPendingForMulligan` returns the first AI seat found in `pending` without reading its phase, so an AI seat that had declared would be driven again and fail its submission (frontend logic over engine state, which the project forbids adding).
With the declaration held outside `pending`, all three are correct by construction and none is edited. `MulliganDecisionEntry` and `MulliganDecisionPhase` are **not changed** (the plan's diff of `MulliganDecisionEntry` is empty; the charter's third claim is satisfied by that).

Invariant, asserted in V4: after every `handle_mulligan_decision`, `handle_mulligan_bottom` and elimination prune, either `pending` is non-empty, or the flow has moved on (round closed and the game started). `pending` empty with `declared` non-empty never rests (it would leave `acting_authority` empty, a hang); `advance_after_decision` closes the round in that case (3.4).

Phase 13 seam: FreeReveal is a second kind of held declaration. It adds a typed kind field to `MulliganDeclaration` (Phase 13 owns that edit; the struct literal sites are all in `mulligan.rs`), and the close routine's single exhaustive match on that kind is where it plugs in. No placeholder variant is added here.

### 3.3 The dealer: `deal_sequence` (pure order) and `deal_hands` (the one pregame deal)

In `mulligan.rs` (charter scope: "the dealer primitive"):

```rust
/// CR 103.5 + CR 121.2c as modified by the format's `DealOrder`: the recipient of each successive card.
pub(crate) fn deal_sequence(state: &GameState, deals: &[(PlayerId, usize)]) -> Vec<PlayerId>
```
- `let order = apnap_order_from(state, None, state.active_player)` (`game/players.rs`, `pub`; with `None` it starts at the active player and skips eliminated seats; its existing unit test `apnap_order_from_none_defaults_to_active_player` pins that). `ordered` = `deals` re-ordered by `order` (a seat in `deals` but not in `order` is dropped).
- `match state.format_config.format.deal_order()` exhaustive: `PlayerByPlayer` yields each player's count repeated, in order (CR 121.2c: the active player performs all of their draws first); `Interleaved` yields, for `round in 0..max_count`, each ordered player whose count exceeds `round`, i.e. one card at a time round-robin with uneven counts handled.
- Pure over `&GameState`: it does no draw, so Phase 14's pause-capable in-game dealer frame and Phase 15's Day's Undoing consume the same function and perform each slot through their own draw machinery (their phases state that; this phase does not edit `draw.rs`).

`deal_hands(state, deals, events)` is the one pregame deal: `for each recipient in deal_sequence(..)` call `draw_one`, and after a player's **last** slot push that player's `GameEvent::CardsDrawn { player_id, count }` (count = the requested count, as `draw_n` pushes today). Emitting at the player's last slot reproduces `draw_n`'s existing event order exactly under `PlayerByPlayer` (seven `ZoneChanged`, then that player's `CardsDrawn`, then the next player) and gives P0's `CardsDrawn` before P1's last card under `Interleaved`.

`draw_one(state, player, events) -> bool` is the loop body of today's `draw_n` moved verbatim (read the top card of the player's library through whatever accessor Phase 6 put there, `ZoneMoveRequest::pregame(top, Zone::Hand)` with Phase 11's `.performed_by(player)`, `move_object`; returns false on an empty library). `draw_n(state, player, count, events)` becomes `deal_hands(state, &[(player, count)], events)`, so Serum Powder's redraw and the eager `Mulligan` redraw keep their exact behavior (one recipient: both orders reduce to `count` consecutive draws; `count` is never 0 at any call site, measured by reading the three callers: opening deal 7, redraw 7, Powder `exiled_count` of a hand that contains the Powder itself).

`start_mulligan` replaces its per-seat `draw_n` loop with `deal_hands(state, &seat_order.iter().map(|&p| (p, STARTING_HAND_SIZE)).collect::<Vec<_>>(), events)`. Non-shared preservation: `start_game_with_starting_player` rotates `seat_order` so the starting player is first and sets `active_player` to the starting player (measured by reading `engine.rs`: `state.seat_order.rotate_left(idx)` and `state.active_player = starting_player`), so `apnap_order_from(None, active_player)` equals `seat_order` at the deal and `PlayerByPlayer` reproduces the old loop; V2c pins the event sequence.

### 3.4 The round: record at declaration, close when nobody owes an action

`handle_mulligan_decision` (the `Mulligan` arm only changes; `Keep` and `UseSerumPowder` arms are untouched):

```rust
MulliganChoice::Mulligan => match mulligan_timing(state) {
    MulliganTiming::Immediate => { /* today's body, unchanged: shuffle_hand_into_library, draw_n, count + 1, cap check */ }
    MulliganTiming::Simultaneous => {
        // CR 103.5: record the declaration; the hand stays until every player has declared.
        let entry = pending.remove(idx);
        declared.push(MulliganDeclaration { player, mulligan_count: entry.mulligan_count });
    }
}
```
`pending`/`declared` are cloned from `state.waiting_for` at the top (as `pending` is today) and threaded into `advance_after_decision`, whose signature gains `declared: Vec<MulliganDeclaration>` (private; `handle_mulligan_bottom` is its other caller and forwards the field it destructures).

`advance_after_decision(state, pending, declared, free_first, events)`:
1. `pending` non-empty: return `MulliganDecision { pending, declared, free_first_mulligan }`. A `BottomCards` entry keeps the round open, so a seat that kept and still owes bottoms places them on the pile bottom **before** another seat's held mulligan shuffles the pile (CR 103.5 order: the bottoming belongs to the mulligan that precedes the next declaration round; V4d).
2. `pending` empty and `declared` empty: today's finish (`prepaid_mulligan_bottoms.clear()`, `finish_mulligans`).
3. `pending` empty and `declared` non-empty: **close the round**, then re-enter this function with the new `pending` and empty `declared` (terminates: the closed round leaves no `declared`, and `pending` is then empty-finish or non-empty-return).

`close_declare_round(state, declared, free_first, events) -> Vec<MulliganDecisionEntry>` (CR 103.5 "all players who decided to take mulligans do so at the same time"):
- `redrawers` = `declared` ordered by `apnap_order_from(state, None, state.active_player)` (arrival order is irrelevant: V4c has the non-active seat declare first).
- Every redrawer's hand is returned (`return_hand_to_library`, the existing pipeline moves with `.at_library_position(Bottom)` split out of `shuffle_hand_into_library`), **then each distinct library container is shuffled once** (`shuffle_library_of`, the Phase 6 holder-seat shuffle idiom split out of the same function; distinct holders via `zone_storage_seat(Zone::Library, p)` de-duplicated, so a shared pile is shuffled once for N redrawers). `shuffle_hand_into_library` (eager arm) becomes `return_hand_to_library` + `shuffle_library_of`, behavior unchanged, so `mulligan_shuffle_back_emits_no_shuffled_library_events` keeps its meaning and V4c asserts the same zero-event property for the round.
- For each redrawer: `new_count = mulligan_count + 1`, `state.prepaid_mulligan_bottoms.insert(player, 0)` (a fresh redraw voids any prepaid credit, as the eager arm does).
- `deal_hands(state, redrawers.map(|p| (p, STARTING_HAND_SIZE)), events)`: one deal, interleaved under Dandan, so the new hands are dealt alternately active-player first.
- Rebuild each redrawer's entry `{ player, mulligan_count: new_count, phase: Declare }`; if `new_count >= max_mulligans_for(free_first)` call `resolve_declare_point(.., PendingMulliganAction::Keep, ..)` on it (the same implicit Keep at the cap the eager arm applies; it owes `bottom_count_for(new_count)` bottoms or leaves `pending`).
- Returns the entries in `state.seat_order` order (the order `pending` already uses).

Serum Powder stays an immediate action under the round (CR 103.5b: the player performs the action, then declares; "other players may have already made their mulligan declarations"): `handle_serum_powder` runs at its declare point exactly as today, drawing its redraw from the pile through `deal_hands`/`draw_n`, and the entry returns to `Declare`. A player whose mulligan is already in `declared` is not in `pending` and cannot use a Powder afterwards (V4e), matching CR 103.5b's "they then declare".

`handle_mulligan_decision`'s refusal of an entry not in `Declare` keeps its text; a player in `declared` is not in `pending`, so a second submission hits `check_actor_authorization` (`WrongPlayer`, because `acting_players()` reads `pending`) before reaching the handler, and the handler's own "not in the pending set" error is the defense in depth.

### 3.5 Elimination while declarations are held (CR 800.4a), a required edit outside the charter list

`elimination.rs::prune_mulligan_pending` filters `pending` to living players and, if that empties it, calls `mulligan::finish_mulligans_public`. Under the round that is wrong when `declared` still holds a living player: the game would start with a declared mulligan never carried out. Measured by reading the function: it destructures `WaitingFor::MulliganDecision { pending, free_first_mulligan }` and has no notion of `declared`. Edit: it also filters `declared` to living players and replaces both manual branches (the `alive.is_empty()` finish and the rebuilt `WaitingFor`) with one call to a new `pub(crate) fn settle_mulligan_pending(state, pending, declared, free_first, events) -> WaitingFor` in `mulligan.rs`, which is `advance_after_decision` exposed (it already handles non-empty `pending`, empty-finish and the round close). `finish_mulligans_public` loses its only caller and is removed (`git grep -n finish_mulligans_public -- crates` shows `elimination.rs` and its definition only); `enter_normal_mulligan_public` (the `OpeningHandBottomCards` branch) stays. Non-shared behavior is identical (`declared` is always empty: the non-empty-alive branch rebuilds the same `WaitingFor`, the empty branch clears the ledger and finishes, as `advance_after_decision` does). Dandan is 2-seat so the reachable case is a concede during the round (the game ends); the class case is any shared-library format with 3+ seats, exercised by V4g with a 3-seat state whose format is set to Dandan.

## 6. Sizing
