## Findings

**[MED]** [behavior] The pregame deal order changed for shared-team-turn formats (Two-Headed Giant), and the active player is dealt SECOND when it is not the first seat of its team. Evidence: `deal_sequence` in crates/engine/src/game/mulligan.rs takes `apnap_order_from(state, None, state.active_player)`, which delegates to `topology::apnap_order_from` when `has_shared_team_turns()` and lists team members in `state.players` order. Probe (candidate vs base, `start_game_with_starting_player`, 4-seat `FormatConfig::two_headed_giant()`, recipient of each Library->Hand move): start=P1 base `[1,1,..,2,..,3,..,0,..]` (seat_order), candidate `[0,..,1,..,2,..,3,..]`, and `CardsDrawn` order `[1,2,3,0]` -> `[0,1,2,3]`; start=P3 base `[3,0,1,2]`, candidate `[2,3,0,1]`; start=P0/P2 identical. Archenemy (3 seats) identical. Why it matters: it is a non-Dandan behavior change the plan's identity claim ("apnap equals seat_order at the deal") does not hold for, no test pins it (full suite green with it), and it contradicts the arm's own CR 121.2c comment (active player draws first) in exactly the case the change introduces; the same primitive is what Phases 14/15 consume. Game state is unaffected (per-library draws, no RNG), so this is event/animation order only. Decision: not rules-mandated either way (CR 103.5 sets no opening-draw order; CR 103.5d orders only declarations), so the fix is to keep the old order and say so. Suggested fix: anchor the order on the active player explicitly (active player first, then the rest of the apnap order), or have the `PlayerByPlayer` arm iterate `state.seat_order` (already rotated active-first at the pregame deal) and keep `apnap_order_from` for `Interleaved`; add one 2HG start-with-P1 test asserting `[1..,2..,3..,0..]` (red on the current candidate, green on base).
