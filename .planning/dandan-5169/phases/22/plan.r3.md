# Phase 22 plan (r2) — S9b host-supplied Dandan pile, client flows (PHASE_BASE_SHA d12daf57938f9d9db5762f20ed36ff1d4c76701e)

## Shape of the code (derived from one entry-point trace per route; no architecture file states the client's start-flow shape)

Five parts own the decisions. (1) Entry UIs choose what to start: `GameSetupPage` (local AI, navigates to `/game/<id>?mode=ai&format=…`), `MultiplayerPage` (`handleHostSetupComplete` → `executeAction` host: P2P via `startP2PHostingSession(settings, deck, …)`, server via `startHosting(settings, deck, url)`; join via `handleJoinGame` / the `deckRejected` re-entry effect → `executeAction` join → `/game/<id>?mode=join|p2p-join`), `HostSetup` (the host form) and `HostControlTile` (live AI-seat edits). (2) `GamePage` parses the URL into `formatConfig`/`matchConfig` and renders `GameProvider`. (3) `GameProvider` builds the `DeckListPayload` per route (local AI wasm, native AI, P2P host/guest, online host/join) and hands it to the adapter. (4) The P2P host's `validateGuestDeck` (`evaluateDeckFormatGate`) is the authority on a P2P guest's deck and answers a refusal with `kick{format}`; a server `mode=join` guest is never format-gated. (5) The engine decides legality (`evaluateDeckCompatibility`) and the supply axis (`deckSupplyForFormat`, wire strings `PlayerBuilt|EngineFixed|HostPile`, Phase 21). The client is a transport/display layer: it asks the engine and dispatches. `formatSuppliesDeck` (registry flag, sync, true for Momir and Dandan) answers "this player builds no deck" and stays the guest/AI-seat/lobby-requirement predicate; the engine's `deckSupplyForFormat` distinguishes `HostPile` and is asked only where the pile is chosen or the pile seat is built.

## Claims re-measured at the base (instrument = scratch copy of `client/` under `dandan-run/scratch/`, real wasm + `card-data.json`, vitest; deleted after)

1. **"One helper builds every empty-seat deck" is false at base.** `rg -n 'main_deck: \[\]' client/src` (non-test, excluding `wasm/`) lists the literals in `GameProvider.tsx`, `multiplayerStore.ts`, `multiplayerDraftStore.ts`, `brokerClient.ts` and `p2p-adapter.ts`; the same pattern hits `buildLocalAiDeckList` (control). Premise corrected: the plan introduces the one builder (`services/pileSource.ts`) and routes every GameProvider literal and every host-deck/AI-seat-deck construction for a supplied format through it; broker registration placeholders, the draft store, adapter defaults and the lobby host's own `opponent` placeholder (empty for every format) are not pile-affected seats and stay.
2. **The legality verdict already exists and is the pile's gate.** Real `evaluateDeckCompatibility`: an 80-card Jund list for Dandan is compatible with no reasons; 60 Forest is incompatible ("Dandân deck must have exactly 80 cards (found 60)"); the empty deck is incompatible ("found 0"), so the Default pile bypasses the hint and never submits through it; the same 80 for Momir is incompatible. The picker displays this verdict for a named deck; the client counts nothing.
3. **Engine accepts the pile end to end (U1 mechanism).** Real `initialize_game`: Dandan with a named 80-card pile on the pile seat and an empty deck on the other seat starts with 66 library objects after the two opening draws (80 in all) and without the default list's `Dandân`; Dandan all-empty starts with `Dandân` present; Momir all-empty starts; Momir with an 80-card list on the player is refused ("exactly 60 cards"/"snow basics only"), so EngineFixed must submit empty (addendum line 1).
4. **Existing GameProvider suites cannot reach the new code.** `joinOrigin`, `nativeEngine`, `p2pHostLifecycle` mock `formatSuppliesDeck: () => false` (`p2pHostLifecycle` replaces `data/formatRegistry` wholesale with that one export), mock `services/deckParser` with only `expandParsedDeck`, and spread `constants/storage`. `pileSource.ts` imports only `expandParsedDeck`, `loadSavedDeck`, `deckSupplyForFormat` and no `formatRegistry` name, so those suites stay green; driven: a probe module of that shape imported by GameProvider leaves the three files passing, and throwing from it fails all three.
5. **Server and P2P transports ignore non-pile seats.** The P2P host adapter reads only `hostDeckData.player`; `validateGuestDeck` gates a guest through `evaluateDeckFormatGate` (empty accepted for supplying formats, `e2_the_p2p_guest_gate_admits_an_empty_dandan_submission`); server join/seat mutation only name-resolves decks (`resolve_deck_empty_deck_is_ok`). Rematch (`GamePage` `handleRematch`) copies the URL searchParams, so `pile` survives it.
6. **No tournament/draft route reaches a supplied format.** `rg -c format client/src/pages/TournamentLandingPage.tsx` prints nothing; the control `rg -c format client/src/pages/GameSetupPage.tsx` prints a count. `rg -n formatSuppliesDeck client/src` (non-test, excluding `data/formatRegistry.ts`) names only `GameProvider`, `GameSetupPage`, `AiOpponentConfig`.
7. **The host gate is the format oracle for a guest, driven.** Real `evaluateDeckFormatGate` (the call `validateGuestDeck` makes): Standard + empty → incompatible ("at least 60 cards (found 0)"); Dandan + empty → compatible; Dandan + 60 Forest → incompatible; Dandan + the 80 Jund list → compatible; Momir + empty → compatible; Momir + 60 Forest → incompatible. `deckSupplyForFormat` answers `HostPile`/`EngineFixed`/`PlayerBuilt` for Dandan/Momir/Standard. Consequences used below: an empty dial is admitted by every supplying room and, by a PlayerBuilt room constructed with a `formatConfig`, answered by `kick{format}` (`handleNewGuest` gates only `if (this.formatConfig)`; `GameProvider`'s fresh p2p-host never has one in production, so that room seats any submission); a supplying room kicks only a non-empty non-pile submission; a re-dial with an empty submission is admitted, so a re-entry loop terminates after one extra dial.
8. **No handshake field carries the format before the deck.** `rg -n '"guest_deck"|kick.*format' client/src/adapter/p2p-adapter.ts`: the guest's first message is `guest_deck` (the host rejects any other first message), and the host's format reaches the guest only as `kick.format` (surfaced as the `deckRejected` event's `format`, which `GamePage` hands back to `MultiplayerPage` as router state) or in the post-admission seat snapshot. A raw 5-character P2P code (no lobby listing) therefore cannot know the format before dialling, and answering it earlier would need a wire field; the charter expects none and none is added.
9. **Base is red where the plan changes behaviour, driven.** `MultiplayerPage` host (stubbed `HostSetup`, `onHost` invoked): Dandan with no active deck leaves host-setup and never calls `startHosting`; Momir and Dandan with an active deck the engine calls illegal are refused with the engine reason and never call `startHosting`. Raw-code `onJoinGame("ABCDE", null)` with no active deck reaches deck-select and performs no navigation. The `deckRejected` re-entry with `format: "Dandan"` toasts and reaches deck-select. `GameProvider`: `p2p-join` with no active deck and no format raises `onNoDeck` and builds no guest adapter; `p2p-join` and fresh `p2p-host` with a supplied format and an active deck hand that active deck to the adapter. `HostControlTile` with a Dandan session and an empty AI catalog: Add AI and Fill with AI are both disabled.

## Decision

1. `engineRuntime.deckSupplyForFormat(format): Promise<DeckSupply>` beside `bestOfThreeCeilingForFormat` (same `ensureWasmInit` + `loadEngineModule` shape). `DeckSupply` lives there; the substring `deck_supply` is added to neither `adapter/types.ts` nor `data/formatRegistry.ts` (binding line 2; the Rust census file stays untouched).
2. New `services/pileSource.ts`, the single builder named by the charter: `PileSource = {type:"Default"} | {type:"SavedDeck"; name}`, `emptySeatDeck()`, `suppliedAiDeckChoice()` (the `{id, label, choice}` entry `HostControlTile`'s `deckChoices` carries, its `choice` an empty `DeckList` built from `emptySeatDeck()`; the dropdown is hidden so the label is never shown), and `pileSeatDeck(format, source)`: `SavedDeck` asks the engine and returns the expanded saved deck only for `HostPile`, else (Default, EngineFixed, PlayerBuilt) the empty deck without any engine call; a vanished saved deck returns `null`. Every GameProvider empty-seat literal and every host-deck/AI-seat-deck construction in the route table uses it.
3. New `components/menu/PileSourceChoice.tsx`: asks `deckSupplyForFormat` (component-local hook, `useBestOfThreeCeiling` pattern: null until it resolves for exactly this format, failure answers `PlayerBuilt`), renders nothing unless `HostPile`, offers Default / saved deck (`listSavedDeckNames`), and for a named deck displays the engine's `selected_format_reasons` from `evaluateDeckCompatibility`. It is the only HostPile gate and every host mounts it for every format; pages hold `{source, legal}` (initial Default/legal, reset to it on a format change), which the component updates through `onChange` (`legal` false while a named verdict is pending or incompatible).
4. Carriers: `pile=<name>` on the local-AI game URL (setup page and the all-AI lobby branch), `settings.pile` on lobby hosts, `format=<GameFormat>` on supplied-format join URLs. The pile choice is not persisted across sessions (charter).
5. Docs: the `deck_supply_for_format` doc sentence ("the lobby offers a pile choice only for `HostPile`") stays true (the picker renders only for `HostPile`; C5 guards it), so no d.ts regeneration. The `from_lobby_config` doc in `crates/engine/src/types/custom_format.rs` is corrected in this phase (one comment sentence: the built-ins that set `supplies_fixed_deck` are Momir and Dandân, both rejected below), binding line 4; a function doc is not exported to the d.ts.
