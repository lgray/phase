## 3. Design

### 3.1 Types (`types/game_state.rs`, draw-sequence types only)

```rust
/// CR 121.2 + the format's `DealOrder`: the seats of ONE simultaneous draw instruction.
pub struct DrawDealer { pub stage: DrawDealerStage, pub seats: Vec<DrawDealerSeat> }
pub enum DrawDealerStage {
    /// CR 121.2a: instruction counts settle in dealing order; `next` indexes the seat whose instruction the frame holds.
    Settling { next: usize },
    /// The recipient of each individual draw still owed, next first.
    Dealing { schedule: Vec<PlayerId> },
}
pub struct DrawDealerSeat { pub player: PlayerId, pub count: u32, pub applied: HashSet<AppliedReplacementKey> /* deterministic_serde::hash_set, default */, pub accumulated: u32 }
```
`DrawSequenceFrame` gains `#[serde(default, skip_serializing_if = "Option::is_none")] pub dealer: Option<DrawDealer>`. A frame without a dealer serializes byte-identically to today (W4), so every non-shared flow is unchanged on the wire.

Working-copy rule (the one invariant that lets every existing consumer stay unedited): **the frame's own `player`, `applied`, `accumulated`, `pending_delivery` are the working copy of the seat `frame.player`; `dealer.seats` is the durable table, synced whenever the frame changes seat and at completion.** `engine_replacement.rs` credits `frame.accumulated` where `frame.player == player_id`, `settle_draw_instruction` writes the frame where `frame.player == player_id`, and `pending_delivery` belongs to the unit that parked: all three hold because a seat switch happens only at the next unit's take, after `pending_delivery` was consumed, never at a park. `engine_replacement.rs` is therefore not edited (it is outside the scope rule; this phase proves it needs no edit by V5).

`DrawSequenceFrame::begin_next_unit(&mut self) -> (PlayerId, HashSet<AppliedReplacementKey>)` (game_state.rs, next to the struct): for a frame without a dealer it returns `(self.player, self.applied.clone())`; with a dealer in `Dealing`, it pops the schedule's front recipient, and when that recipient is not `self.player` writes `accumulated`/`applied` back to the current seat's entry and loads the recipient's. `debug_assert!(self.pending_delivery.is_none())`. `DrawSequenceStack::validate` gains: dealer seats are distinct; `Settling.next < seats.len()`; in `Dealing` every schedule entry names a seat and `frame.remaining == schedule.len()`; a dealer frame's `origin` is `Plain`. `loop_equal` compares `dealer` as well (CR 104.4b position equality: two states mid-deal at different stages are different positions).

### 3.2 The dealer (`effects/draw.rs`)

Entry points (both `pub(crate)`, consumed only by `effects/mod.rs`):
- `plan_simultaneous_draw(state: &GameState, seats: &[(PlayerId, ResolvedAbility)]) -> Option<Vec<DrawDealerSeat>>`: the shape gate **and** the per-seat instruction count, in one pass so the gate and the count can never disagree. `Some` only when all hold: `seats.len() >= 2`; `state.format_config.format.shared_zones().library == ZoneScope::Shared` (the charter's axis; every other format returns `None` and keeps the sequential fan-out); for every seat, `ability.effect` is `Effect::Draw { count, target }` with `!count.peel_up_to().1` (an "up to" count is the drawer's announced choice, a prompt the dealer does not own), `scoped_library_search::has_no_resolution_riders(ability)` (the shared rider list: no sub, else, condition, optional, repeat, unless-pay, modal, replacement_applied, ...; section 3.3), and `resolve_player_for_context_ref(state, ability, target) == seat player` (the bound ability really draws for that seat). The count is `resolve_quantity_with_targets(state, count, ability).max(0) as u32` for **every seat before any card moves** (CR 121.2a: instruction counts settle before any individual draw; also the only simultaneous reading of a count that depends on the board). `applied` = the ability's `replacement_applied` (empty by the rider predicate).
- `start_simultaneous_draw(state, seats: Vec<DrawDealerSeat>, events) -> SimultaneousDraw { Completed { delivered: Vec<(PlayerId, u32)> }, Parked }`: pushes one frame (`state.push_draw_sequence_with_origin(first.player, 0, first.applied, Plain)`), sets `frame.dealer = Some(DrawDealer { stage: Settling { next: 0 }, seats })`, consults seat 0's instruction (3.2.1), then runs the existing driver `resume_draw_sequence_outcome`.

3.2.1 **Consult extraction.** The instruction consult inside `start_draw_sequence_with_origin_outcome` (push-then-consult: `count == 0 || !draw_instruction_may_be_replaced` skips it and owes `count` directly, else `draw_through_replacement_with_applied(.., Instruction, .., settle_draw_instruction)` and a `Parked` return on `NeedsChoice` or when the frame is no longer active) moves verbatim into `consult_draw_instruction(state, frame_id, count, applied, events) -> Result<(), DrawSequenceOutcome>`; both the single-seat start and the dealer call it. Behavior of every existing caller is unchanged (the existing draw tests are the guard, V10).

3.2.2 **Driver edits in `resume_draw_sequence_outcome`** (the single post-pause driver):
1. After the pending-delivery step and before taking a unit, `if the frame's dealer is Settling { next }`: invariant "seat `next`'s consult has completed and its settled count is `frame.remaining`" (true on first entry from `start_simultaneous_draw` and on every resume after a consult parked, because `settle_draw_instruction` has then written the frame). Record `seats[next].count = frame.remaining` and `.applied = frame.applied`, then either (a) load seat `next + 1` into the frame (`player`, `applied`, `remaining = 0`), set `Settling { next + 1 }` and `consult_draw_instruction` for it, returning `Parked` when it parks and re-looping otherwise; or (b) after the last seat, build the schedule with the shared order core (3.3) over `(player, settled count)` in seat order, set `frame.remaining = schedule.len()` and `Dealing { schedule }`. A seat whose settled count is zero simply owes nothing (Alms Collector's replaced instruction).
2. The unit take replaces `let player = frame.player; let applied = frame.applied.clone();` with `let (player, applied) = frame.begin_next_unit();`. Everything else in the loop (the `remaining -= 1` before the attempt, `draw_through_replacement_with_applied(.., Individual, ..)`, pending-delivery parking, nested-frame crediting by id, `Parked` on nested frames) is unchanged: the unit is one ordinary single draw for `player`.
3. Completion (`pop_active_draw_sequence`): for a dealer frame, first write the active seat back, then for each seat in dealing order emit `PlayerPerformedAction { Draw }` when its `accumulated > 0` (the same per-instruction granularity the single-seat branch uses), and publish the delivered counts (3.4); `state.last_effect_count`, `origin` handling and the post-replacement/continuation tail below are the existing code. The `Completed` carrier's `delivered` is the sum.

The dealer has **no yield point of its own**: it is a loop inside one dispatch that returns only on completion or when the replacement pipeline parks (a unit's replacement choice, a nested instruction, an instruction consult). That is the S6 design statement (3.5).

### 3.4 Intercepts and publication (`effects/mod.rs::resolve_chain_body`)

Helper: `bind_scoped_seat(template: &ResolvedAbility, controller: PlayerId, seat: PlayerId) -> ResolvedAbility` = clone + `set_original_controller_recursive(controller)` + `set_controller_recursive(seat)` + `set_scoped_player_recursive(seat)`, the three-call sequence now written out twice in the driver (the in-loop iteration and the continuation builder). Both existing sites and the new one call it (no fourth copy).

**Layer 1, the `player_scope` driver.** After `split_player_scope_chain` and the sacrifice and scoped-search branches, before `initial_waiting_for`: build `seats = matching_players.map(|pid| (pid, bind_scoped_seat(&scoped_template, controller, pid)))`; when `!after_scope_needs_linked_exile && !next_sub_needs_tracked_set(ability)` (a tail that consumes "the cards drawn this way" keeps the sequential fan-out; Phase 15 widens this for Day's Undoing) and `draw::plan_simultaneous_draw(state, &seats)` is `Some(instructions)`:
- `Parked`: `append_to_pending_continuation(state, after_scope)` (the unscoped tail drains at the existing boundary after the dealer's frame completes) and `return Ok(())`.
- `Completed { delivered }`: push one `EffectResolved { kind: Draw, source_id }` per seat (parity with the per-iteration `draw::resolve`), call `publish_player_scope_clause_results(.., &matching_players, false, &events[scoped_events_before..])` (the clause's one terminal-publication authority: `last_zone_changed_ids`, scalar fallback), then **re-install the dealer's table** (`install_previous_effect_counts_by_player(state, Some(table), false)`) because that generic publication takes the `None` arm for a non-event-producer kind and clears the table; set `state.clause_minimum_snapshot = None`; run `after_scope` through `resolve_ability_chain(.., depth + 1)`; `return Ok(())`.

**Layer 2, `resolves_for_each_target_player`.** After `fanout_players` is computed (so `chosen_players.len() >= 2`): `seats = fanout_players.map(|pid| (pid, per_target with targets = [Player(pid)], multi_target = None))`; when `plan_simultaneous_draw` is `Some`: `Parked` -> `append_to_pending_continuation(state, after_fanout)`; `Completed` -> one `EffectResolved` per seat, then `after_fanout` through `resolve_ability_chain`; both `return Ok(())`. The sequential path for this layer never calls the clause publisher, so none is added.

**Table publication (charter: `install_previous_effect_counts_by_player`).** The dealer is a per-player count producer for `Draw`: at completion (in `draw.rs`, so a completion reached after a pause on the replacement-choice resume path publishes too) it calls `super::install_previous_effect_counts_by_player(state, Some(table), false)` with `table = { seat -> accumulated }` over **every seat of the instruction** (zero-filled: CR 608.2c, a seat that drew nothing drew zero this way). It sets `last_effect_count` and `last_effect_amount` to the sum and `last_effect_counts_by_player` to the table, so each seat's delivered count survives interleaving and any number of pauses (each seat's `accumulated` lives in the table while another seat is the working copy). This is a second producer beside the event-keyed `previous_effect_counts_by_player_from_events` (which stays closed over Discard/DiscardCard/ChangeZoneAll; its test `count_authority_producer_set_is_closed_over_effect_kind` stays true and is not edited). Doc comments that call `Draw` a non-producer (`quantity.rs` Max/Min fallback note, `ability.rs` `PreviousEffectAmount.aggregate` doc) are corrected in the same change (comment-only; section 9).

## 4. Required architectural answers

**Pattern Coverage (charter attribution).** The class is "an instruction that makes several players draw at once, in a format whose library is shared": census of `client/public/card-data.json` (python walk over `abilities` and `triggers[].execute`, regenerable): 33 ability or trigger heads (32 cards) whose root effect is `Draw` with a `player_scope` and no `sub_ability`, e.g. Prosperity, Skyscribing, Fascination, Vision Skeins, Temple Bell, Howling Golem, Jace Beleren, Mutual Epiphany, Temporal Cascade (the `Opponent`-scoped heads engage the dealer only with two or more opponent seats, and the two "up to" heads, Indentured Djinn and Shah of Naar Isle, keep the sequential fan-out by the gate); plus the "target players each draw" layer (Jace, Memory Adept; Huddle Up; Gleaming Splendor; Donatello's Science Lesson). The Dandan decklist itself has no such card (Day's Undoing is Phase 15's consumer), which is why Prosperity is the proof card.

**Sizing.** Units: **1**.
