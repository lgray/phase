## Findings

### B1 [behavior] Plan departs from the required typed word-vs-symbol discriminator

Departures (every one is the same decision; list is the scope of the replan):

1. Decision section: "Carrier = `SYMBOL`; both word-form emitters are deleted; no discriminator." Required: a typed provenance field, no blanket SYMBOL, no emitter deletion.
2. Step 1 (`WORD_CARRIERS` row flips to `SYMBOL`), Step 2 (delete `try_extract_adamant_condition` and its call), Step 3 (delete `parse_word_mana_color_spent_condition`, reduce the `alt`), Step 4 (rewrite the "LEGACY SHAPE" docs to "symbol-only"), Step 5 (replace `extract_adamant_three_red`, which pins an emitter the required design keeps).
3. Claims 2-3 and the Ladder paragraph justify the departure by reachability ("no printed card reaches a word emitter"). The reviews' contract is provenance carried by the condition; reachability by a printed card is not the criterion (the maintainer: "`oracle_trigger.rs:9918` and `:9967` still emit the shared trigger condition from word and symbol forms").
4. Expected scope lists `types/ability.rs` as doc-only; the required design changes both condition enums, so it is a type change (charter scope rule: `types/ability.rs` "only if the discriminator branch applies" — it applies).
5. "No serialized shape changes ... no protocol constant, wire version or binding changes" is false under the required design.
6. Verification rows R6, R7a, R8 and mutation M2 assert the deleted-emitter design (word-form trigger text must parse to `QuantityComparison`/no `ManaColorSpent`).
7. Sizing says six paths with `ability.rs` comment-only; the required design adds the compiler-forced consumers (admitted standing class) and the protocol/bindings surfaces.

Maintainer claims verified by command (HEAD 1cf3bd4c85):
- `conditions.rs` doc `parse_symbolic_mana_color_spent_condition above is NOT shadowed` at `/usr/bin/grep -n "NOT shadowed"` -> line 5141; the word parser's doc says "SHADOWED, kept as a fallback only" (not claimed live). Matches the review.
- `awk 'NR==9918||NR==9967'` on `oracle_trigger.rs`: 9918 `Some(TriggerCondition::ManaColorSpent { color, minimum: n })` (Adamant, word), 9967 `[(color, minimum)] => TriggerCondition::ManaColorSpent {` (symbolic, in `SymbolicManaSpentIntro::condition`; 9974 the `And` leaves). Both emit the same variant.

Concrete design the replan needs:

- **Type.** One new closed enum in `types/ability.rs` (not a `bool`; no existing enum fits: `/usr/bin/grep -n "^pub enum \w*\(Symbol\|Word\|Lexical\|Provenance\|Surface\)"` finds none for this axis), e.g. `ManaSpendForm { Word, Symbol }`, as a required field on BOTH `AbilityCondition::ManaColorSpent` and `TriggerCondition::ManaColorSpent`. Both must carry it: `WORD_CARRIERS` keys on the serialized `type` tag `"ManaColorSpent"`, shared by the two enums, and each enum has a word-form and a symbol-form producer. Prefer no `#[serde(default)]` (a default hides an emitter that forgot to set it; card-data and the integration fixture are regenerated, alpha saves may break per standing decision). If the replan prefers the nested-tag shape (`color` held by a tagged value whose own `type` tag is the provenance), the existing nearest-tag keying needs no walker change; with a sibling field, `walk_strings` must hand the visitor the enclosing object's provenance.
- **Emitters set it** (population: every producer of the variant, regenerated by `/usr/bin/grep -rn "ManaColorSpent *{" crates/engine/src`): `parse_symbolic_mana_color_spent_condition` (both the single and the `And` leaves) -> Symbol; `parse_word_mana_color_spent_condition` (kept, shadowed) -> Word; `try_extract_adamant_condition` -> Word; `SymbolicManaSpentIntro::condition` (single, `And` leaves, `Not` wrapper) -> Symbol. No emitter is deleted.
- **Reader.** Classification stays in `WORD_CARRIERS`/`carrier_class` (single authority for CR 612.2): `ManaColorSpent.color` is Word when the form is Word and `SYMBOL` when Symbol. `classified_word_occurrences`, `unclassified_word_positions` and `rewrite_counted` all go through `walk_strings`, so the discriminator must be readable by that one walker or all three diverge.
- **Compiler-forced sites** (standing class): the destructures `ManaColorSpent { color, minimum }` in `coverage.rs`, `effects/mod.rs` (evaluator), `triggers.rs` (evaluator), `ability_scan.rs`, `ability_rw.rs`, `assembly.rs`, `oracle_effect/mod.rs`, plus the construction sites in inline tests (`oracle_trigger_tests.rs` has 10) and `tests/integration/emptiness_mana_spent_evoke_5943.rs`. The evaluators ignore the field (`{ color, minimum, .. }`); the plan must say so and keep the paid-tally comparison untouched.
- **Serialized shape / protocol / bindings.** The condition is serialized inside ability definitions that ride game state, so this is a wire-shape change and takes the charter's standing protocol bump: re-derive `EXPECTED_PROTOCOL_VERSION` and `EXPECTED_WIRE_PROTOCOL_VERSION` stacking per `common.md` (`grep -oP 'const EXPECTED_\w+ = [^;]+' scripts/check-protocol-version.mjs`), add the title entry the script matches, run `node scripts/check-protocol-version.mjs` and the pin tests. Bindings: measured that `client/src/wasm/engine_wasm.d.ts` has zero mentions of `AbilityCondition` and `crates/engine/src/bin/interaction_bindings.rs` covers only `types::interaction`; the executor still runs `./scripts/check-interaction-bindings.sh --check` (expected no diff). Parse-diff/coverage: the field shows in the serialized AST of the 39 tagged cards (all Symbol); the plan must state it, and the PR body's parse-scope sentence needs the matching update.
- **Verification rows under the required design.** Keep R1-R5 as written (behavior is the same). Replace R6/R7/R8/M2: (a) the word-form trigger text must parse to `ManaColorSpent` with form Word and a Red->Blue rewrite must change it, while `{R}` parses to Symbol and the same rewrite returns `None`; (b) a runtime row for the otherwise unreachable Word trigger producer using `add_creature_to_hand_from_oracle` (the harness works: the same driver with the word-form ETB text ran in my probe and distinguishes RRR / RGG / Red->Blue / Green->Blue by hand size); without it the Word value of the new field has no consumer-side test; (c) census: every export card whose faces serialize `ManaColorSpent` has form Symbol (positive control: count 39), and the mutation is "emit Word from the symbolic parser" -> R1-R4 red, "emit Symbol from the Adamant extractor" -> (a)/(b) red.
- **Sizing.** Re-state units/paths for the discriminator branch: `text_substitution.rs`, `conditions.rs`, `oracle_trigger.rs`, `oracle_trigger_tests.rs`, `types/ability.rs`, `text_substitution_cr612.rs` plus compiler-forced consumers and protocol/bindings pins (standing class). One unit still.

Additional evidence the plan's reachability argument was incomplete even on its own terms (supports keeping the emitter): `extract_adamant_three_red` calls `extract_if_condition` on the trailing form "it deals 4 damage instead if at least three red mana was spent to cast this spell" and expects `TriggerCondition::ManaColorSpent`. With only the emitter removed (my `p20r_synthetic`), the trailing trigger forms ("When this creature enters, draw a card if at least three red mana was spent to cast it.", also the damage form) parse to `OfColor` with NO `QuantityComparison` trigger condition (`P20R-SYN etb-trailing: ManaColorSpent=false OfColor=true QuantityComparison=false`), while the leading forms parse to `QuantityComparison`. Plan claim 3 covered only the three leading texts; the trailing form changes condition shape (trigger-level condition to an ability-level one), which the plan never measured.
