## 4. Design

### 4.1 Read swaps (unit U1)

Each swap lands with the semantic effect it is, per charter D2:

- `zone_eval.rs::graveyard_value`: `state.graveyard_of(player).iter()` replaces `state.players[player.0 as usize].graveyard.iter()`. Effect: under a shared graveyard both seats compute the same sum in the same order, so `zone_bonus`'s `my_score - max_opp` cancels the graveyard term exactly (bit-identical f64 operations), instead of crediting the pile wholly to the canonical seat. Annotation on the function: `CR 404.1 + CR 400.1`: a player's graveyard is the zone `graveyard_of` resolves; one shared graveyard is every seat's.
- `policies/payoff.rs::mill_scale`: `.map(|&opp_id| ctx.state.library_of(opp_id).len())`. Effect: the non-canonical opponent no longer reads 0 and pins `URGENCY_SCALE_HIGH`; the scale follows the real shared pile size. Annotation already `CR 104.3c`; add `CR 401.3` (library size is public).
- `policies/mill_targeting.rs::verdict`: `ctx.state.players.get(idx)` stays as the unknown-seat guard, and the emptiness test becomes `ctx.state.library_of(*player).is_empty()`. Effect: `EMPTY_LIBRARY_PENALTY` stops being always-on for the non-holder seat. Annotation: `CR 401.3`.
- `search.rs::large_board_main_phase_has_no_development_sources`: `player.hand.is_empty()` stays on the per-seat `Player`; `player.graveyard.is_empty()` becomes `state.graveyard_of(ai_player).is_empty()`. Effect: the non-canonical AI seat with a non-empty shared graveyard no longer reads "no graveyard development source" and passes priority instead of considering graveyard abilities. Annotation: `CR 404.1`. Edit stays inside this function (Phase 13 edits other functions of the file).

Not changed, with verdict: the *premise* of `mill_scale` and `MillTargetingPolicy` ("an opponent near decking is good for me") is symmetric under a shared pile (CR 104.3c and CR 121.4 apply to whoever next draws). The charter asks for the read swap only; modeling self-decking from a shared pile is a new policy dimension, not a read, and no Dandan-list card is a mill deck. Dropped with that verdict; no row, no TODO.

### 4.2 Pool resolution (unit U2)

One authority per concept: the engine resolver `GameState::deck_pool_of(seat)` (Phase 6) answers "which pool backs this seat". `phase-ai` adds two `pub(crate)` free functions in `deck_knowledge.rs`, built only on it:

```rust
/// The seat holding the pool that backs `seat`'s deck (the seat itself unless the library is shared).
pub(crate) fn pool_holder(state: &GameState, seat: PlayerId) -> Option<PlayerId> {
    state.deck_pool_of(seat).map(|pool| pool.player)
}
/// Every seat whose deck is the pool held by `holder`.
pub(crate) fn pool_seats(state: &GameState, holder: PlayerId) -> impl Iterator<Item = PlayerId> + '_ {
    state.players.iter().map(|p| p.id).filter(move |&seat| pool_holder(state, seat) == Some(holder))
}
```

`deck_knowledge.rs`:
- The three lookups become `state.deck_pool_of(player)`.
- The owner test `object.owner != player` (in `known_remaining_deck_counts` and `unknown_hidden_pool`) and the `object.owner == player` filters on battlefield and exile (in `public_account_object_ids`) become `pool_holder(state, object.owner) == Some(pool.player)`. In a non-shared format `deck_pool_of(owner)` is the owner's own pool, equal to `pool` iff `owner == player` (pools are one per seat), so the test is the old one; in Dandan it admits every non-token card of the one pile whichever seat owns it. This realizes the charter's "drop the owner filter for shared-zone cards" without a format check or a bool: the building block is the resolver's own identity. A seat with no pool never matches, as before.
- `public_account_object_ids` takes the pool (private function; both callers have it) and reads the graveyard through `state.graveyard_of(player)`: the shared graveyard is added **once** (it is not iterated per pool seat), so a graveyard card subtracts once. Annotation: `CR 400.2` (public zones) `+ CR 400.3` (a card goes to its owner's corresponding zone, so ownership does not say where it sits).
- **Pool/slot reconciliation (the Phase 9 handoff).** `unknown_hidden_pool(state, player, known_ids)` builds the multiset that `determinize_opponents` zips onto `unknown_slots(player)` (player's hand plus the library). Under one pile, the other pool seats' hands are in neither slot set, so their cards must also leave the multiset; at base (and with only the owner-filter change) the observer's own hand would stay in the pool and the zip would hand its copies to the opponent's unknown slots. Edit: in the `seen`-deduped subtraction loop, chain the hands of `pool_seats(state, pool.player).filter(|seat| *seat != player)`. In a non-shared format `pool_seats` is the seat alone, so the chain is empty (identity). `known_remaining_deck_counts` (the owner's own view: "public plus my own hand") deliberately does **not** subtract the co-seat's hand: that would make a tutor/threat read the other hand. Annotation: `CR 401.2` (identity and order of a library are hidden) `+ CR 400.2`. Stated limit (one comment sentence): the co-seat hand is subtracted because Dandan has exactly two seats, so it is the observer's own known hand; a three-seat shared pile would need an observer parameter, which `unknown_hidden_pool`'s only caller (`determinize.rs`, out of scope) does not pass.
- `threat_profile.rs` is unedited if V6 goes green (claim 3): `remaining_deck_view` now finds the pile pool for the non-holder opponent, so `entries` is non-empty and `Some` is returned.

`session.rs::AiSession::from_game`: for each pool, analysis is computed once, then registered (cloned: `DeckProfile`, `DeckFeatures`, `PlanSnapshot`, `StrategyProfile`, `SynergyGraph` are all `Clone`, read) under `pool.player` and every `pool_seats(state, pool.player)` seat. A non-shared format registers `pool.player` only (the chain adds the same key). Seats with no pool keep default entries as before. The doc comment of `from_game` ("Decks not present in `state.deck_pools` get default entries") is amended by one clause.
- **Cache key in lockstep** (same file, same builder): `deck_pools_fingerprint`'s doc says it digests "exactly the inputs `from_game` reads". `from_game` now also reads the seat-to-pool resolution, so the fingerprint additionally hashes `pool_holder(state, seat.id).map(|h| h.0)` for each `state.players` seat; otherwise two states with equal pools but different shared-zone answers would reuse one stale `Arc<AiSession>`. This is a path already in scope (`session.rs`), not an addition. Executor step 0 confirms nothing pins a fingerprint literal: `git grep -n 'deck_pools_fingerprint' -- crates` showed only `lib.rs` (a re-export) and `session.rs` at plan time.

`search.rs::deck_color_demand`: `let Some(pool) = state.deck_pool_of(player) else { return demand };`. No other change. Its other reader (`BetweenGamesSideboard`) stays unedited (claim 4).

## 5. Logic placement, building blocks, idioms

- **Logic Placement.** All "which pool / which container" authority stays in the engine (Phase 6 accessors and `deck_pool_of`). `phase-ai` holds only heuristics, so each edit swaps a data source and keeps the heuristic. The two `pub(crate)` helpers live where the pool is consumed (`deck_knowledge.rs`), and `session.rs` imports `pool_seats`; no helper is duplicated in `search.rs` (it calls `deck_pool_of` directly).
- **Building Blocks.** `GameState::library_of`, `graveyard_of`, `deck_pool_of` (Phase 6); existing `players::opponents`, `PlayerDeckPool`, `DeckProfile::analyze`, `DeckFeatures::analyze`, `derive_snapshot`, `StrategyProfile::for_profile`, `SynergyGraph::build` (unchanged); test scaffolding `GameState::new(FormatConfig::dandan(), 2, seed)`, `create_object`, `GameScenario::new_with_format`, the existing `policies/tests/mill_payoff.rs` fixtures. New helpers justified: `pool_holder` and `pool_seats` serve three sites in two files and encode the resolver identity once.
- **Rust Idioms.** Typed return (`Option<PlayerId>`), no bool, no wildcard match added, iterator chains, no `unwrap` on engine accessors beyond Phase 6's own `expect("seat exists")`; `mill_targeting` keeps its `get(idx)` guard so an unknown seat cannot panic there.
- **Nom Compliance:** not applicable, no file under `crates/engine/src/parser/` changes.
- **Extension vs Creation.** Extends the existing accessor/resolver pattern; creates no new pattern. **Variant Discoverability:** no variant.
- **Analogous Trace.** Traced `remaining_deck_view` end to end: `types/game_state.rs::deck_pool_of` (Phase 6) -> `phase-ai/src/deck_knowledge.rs::{known_remaining_deck_counts, remaining_deck_view, unknown_hidden_pool}` -> consumers `policies/tutor.rs` (own seat), `threat_profile.rs::build_threat_profile_multiplayer` (opponent seat), `determinize.rs::determinize_opponents` (opponent seat, with `unknown_slots`). Traced `AiSession::from_game` -> `SessionCache::get_or_build` (via `deck_pools_fingerprint`) -> `build_ai_context_with_session` (`deck_profile`, `strategy` with default fallback) and `search.rs::deterministic_choice` mulligan branch (`features`, `plan` with default fallback), per the charter.
