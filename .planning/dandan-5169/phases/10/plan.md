**The "your graveyard" reading adopted.** For a card in a shared graveyard or library, "your graveyard" / "your library" is the shared zone for every seat: any seat's "you", "an opponent" or other player reference is satisfied by the shared pile, and a count over "your graveyard" for any seat is the count of the one pile. Source: the announcement the brief quotes verbatim, "Players have a shared library and graveyard. Anything referring to "your" graveyard or library is referencing the shared zone." (brief, Authoritative rules), the brief's Filter owner-axis collapse section ("treat the axis as satisfied for every seat"; "Opponent-scoped text collapses the same way (the July convention)") and the Count dedup section. CR background, each grepped in `docs/MagicCompRules.txt`: CR 400.1 ("Each player has their own library, hand, and graveyard") is the rule the format modifies; CR 400.3 (an object goes to its owner's corresponding zone) and CR 404.1 ("A player's graveyard is their discard pile") are why the stored container is keyed by owner; CR 108.4a + CR 109.5 ("you" for a card with no controller means its owner) are why the engine reads "your graveyard" as an ownership claim. No CR text addresses a shared graveyard; the reading rests on the announcement, and this plan says so rather than citing a CR for it. The "Opponent" half rests only on the brief's July-convention sentence and no Dandan-list card exercises it (the brief says so); it is implemented and tested on Disposal Mummy and Nighthawk Scavenger and flagged in the claims ledger as the brief's call, not a rules derivation.

Charter claim 1 re-measured, and it is false in its consequence: `grep -n matches_target_filter_in_owner_zone crates/engine/src/game/targeting.rs` has no hit, but `targeting.rs::add_zone_targets` and the target re-validation near `matches_target_filter_for_zone` call `filter::matches_target_filter_for_zone`, whose `is_owner_scoped_zone` arm (Hand, Library, Graveyard) delegates to `matches_target_filter_in_owner_zone` (read at `filter.rs`, `matches_target_filter_for_zone`). So target legality for a graveyard object DOES run through the owner-zone function. That function does not skip the controller axis: it overwrites `controller` with `owner` and then runs `filter_inner_for_object`, whose typed-filter controller arm compares `owner` with the source's controller. Consequence for the design: one collapse placed at the typed-filter arm of `filter_inner_for_object`, licensed by the zone the TYPED FILTER ITSELF claims (3.1; never by the zone the object happens to be in), covers both `matches_target_filter` and `matches_target_filter_in_owner_zone`, and `matches_target_filter_in_owner_zone` needs no edit of its own. The charter's "controller collapse is independently required for Mystic Sanctuary" stands (Mystic Sanctuary has only the controller axis), but its stated reason is replaced by this one.

## 3. Design

### 3.1 Unit A: the shared-zone axis collapse (game/filter.rs)

**What licenses the collapse (the F1 correction).** "Your graveyard" is a claim the FILTER makes about a zone, so the collapse is licensed by the zone the typed filter itself names, never by `obj.zone`. The licence is one private function over the same `TypedFilter`'s `properties`:

```text
fn claimed_shared_zone(properties: &[FilterProp], object_zone: Zone) -> Option<Zone>
```
`Some(object_zone)` when a property is `InZone { zone }` with `zone == object_zone`, or `InAnyZone { zones }` with `zones.contains(&object_zone)`; otherwise `None`. A filter with neither property (a sacrifice or destroy observer: `Typed{Permanent, controller You, [Another]}`) is unlicensed and keeps the single existing comparison on the existing value. The explicit `zone` argument of `matches_target_filter_for_zone` is deliberately NOT a licence: `targeting.rs` re-validation (`TargetRef::Object(id)` arm, read) passes `obj.zone` as that argument, so keying on it would be `obj.zone` again. The cards that need the collapse all carry the property (Mystic Sanctuary `InZone Graveyard`; Haunted Fengraf `InZone Graveyard` + `Owned{You}`; Disposal Mummy `InZone Graveyard` + `Owned{Opponent}`; measured in walk W: 1,270 / 142 / 49 cards; the 34 `InAnyZone` cards are licensed by the same rule), so no Dandan row loses reach. (The object's own zone still enters the licence, but only as the value the filter's claim is checked against, so a filter that claims "Graveyard" and meets a battlefield object is unlicensed.)

**One authority for the axis question**, `zone_axis_admits`: does the axis comparison hold against `holder` or against any seat that reads the same container of the licensed zone?

```text
fn zone_axis_admits(state, licensed: Option<Zone>, holder: PlayerId, admits: impl FnMut(PlayerId) -> bool) -> bool
```
- `None` (unlicensed filter, or a record with no origin zone) or a zone whose container is per seat: only `holder` is tried, so every non-shared and every unlicensed case runs the existing comparison exactly once on exactly the same value (identity).
- `Some(zone)` with a shared container: `holder` first, then every other seat `s` in `state.players` with `state.zone_storage_seat(zone, s) == state.zone_storage_seat(zone, holder)`. The seat set is derived from Phase 6's single storage authority; no second Zone-to-`ZoneScope` table is written here. `holder` is always tried even when it is not in `players`.
- `any` over those seats gives the brief's "satisfied for every seat": `You` by the seat equal to the source's controller; `Opponent` by any other living seat; `ScopedPlayer`, `TargetPlayer`, `ChosenPlayer`, `SpecificPlayer` and the rest by the seat the reference names, provided it is a seat that reads the container.

Edits, all in `filter.rs`, all inside the `TargetFilter::Typed` arm of `filter_inner_for_object` (which has `properties` in scope) and its record twin:
1. Typed-filter controller check: compute `let licensed = claimed_shared_zone(properties, obj.zone);` once before the controller check. The existing `match ctrl { .. }` body moves unchanged into a closure `|obj_ctrl: PlayerId| -> bool { match ctrl { ..existing arms, each `return false` rewritten as `false`.. } true }` and the check becomes `if !zone_axis_admits(state, licensed, effective_controller(..), admits) { return false; }`. The arms are not rewritten (they hold the trigger-aware defending-player and chosen-player resolutions; `controller_ref_player` is NOT reused because its `DefendingPlayer` and `TargetPlayer` resolutions differ from the inline arms). The only textual change inside the arms is the `return false` to `false` form that a closure needs, plus rustfmt re-indentation.
2. `FilterProp::Owned`: the isolated `matches_filter_prop` arm cannot see its sibling `InZone`, so the typed loop (which knows `properties` and `licensed`) handles a TOP-LEVEL `Owned` property itself: `properties.iter().all(|p| match p { FilterProp::Owned { controller } => zone_axis_admits(state, licensed, obj.owner, |owner| owned_axis_admits(state, &source_ctx, controller, owner)), _ => matches_filter_prop(p, state, obj, object_id, &source_ctx) })`. The two near-identical 16-arm `Owned` bodies (one in `matches_filter_prop` comparing `obj.owner`, one in `zone_change_record_matches_property` comparing `record.owner`; both take `source: &SourceContext<'_>`) collapse into one `owned_axis_admits(state, source, controller: &ControllerRef, owner: PlayerId) -> bool` (the bodies with `owner` in place of `obj.owner`/`record.owner`, annotations kept). The `matches_filter_prop` and `zone_change_record_matches_property` `Owned` arms each become one call `owned_axis_admits(.., obj.owner)` / `(.., record.owner)` with no collapse, which keeps every nested `Owned` (under `Not`, `AnyOf`, and the like: 7 cards, none with a graveyard/library `InZone` in the same filter, walk W) a single comparison, fail-closed and unchanged. Net effect: two copies become one authority.
3. Record door, `zone_change_filter_inner` (the record twin of the typed arm, `properties` loop at the `zone_change_record_matches_property` call): the same top-level-`Owned` handling with `licensed = claimed_shared_zone_for_record(properties, record.from_zone)` (same rule: the record's `from_zone`, `None` for token creation, is licensed only when a property in the same filter names it). The record TYPED-filter controller check is not collapsed (edit 4a below).
4. `matches_target_filter_in_owner_zone`: no edit (see 0). Its owner override and its `obj.controller == obj.owner` fast path both feed edit 1, and the typed arm sees the filter's `InZone`.
5. Not collapsed, with reasons: (a) the record typed-filter controller axis (`zone_change_filter_inner`'s `record.controller` match) is not collapsed in this phase. V16 (Zulaport Cutthroat: no `InZone`, `from_zone Battlefield`) proves the battlefield-departure case, where `record.controller` must keep meaning the controller at departure. Known boundary (ledger verdict 3b, no landing phase, no list card): a `ChangesZone` valid_card that itself names the pile ('a card in your graveyard is put into your hand', Veteran Ghoulcaller, the only supported trigger with a controller axis and a Graveyard/Library zone) keeps the record-controller comparison, so it ignores cards owned by the other seat. (The licence `claimed_shared_zone_for_record` would admit it at no hostile-row cost; the executor may add it only by returning to the planner.); (b) `FilterProp::Owned` on objects whose zone is per seat (battlefield, hand, stack, exile), and any `Owned` without a naming property (215 cards, walk W), unchanged; (c) the stack-entry controller check and the `FaceControllerScope` arms (no shared zone reaches them); (d) `effects/mod.rs::collect_filter_participants` (the third reader of the axis, which the round-1 review asked about): it does not test membership, it NAMES the participating player from `typed.controller` / `Owned{controller}` via `controller_ref_participant` for a private-zone filter, and the named player is exactly the source-side seat the collapse keeps fixed (the collapse widens which OBJECTS satisfy the axis, never which player the filter names); it is unaffected and untouched.

**Live callers that can reach a graveyard object under `ControllerLookup::LiveOrLki`, and their disposition** (command: `rg -n "valid_card_matches|target_filter_matches_object|matches_target_filter\(" crates/engine/src/game/trigger_matchers.rs`, about 70 hits at HEAD). They fall into three classes: (i) the sacrifice and destroy observers, `match_sacrificed` (live `valid_card_matches_with_lki`, whose comment says "The sacrificed permanent may already be in the graveyard") and `match_destroyed` (a bare live `valid_card_matches` on the already-moved object); (ii) the other leave-the-battlefield and zone-change matchers that fall back to the live object after the record check (`subject_filter_matches_with_lki` users, `valid_card_matches_with_lki` at the other call sites); (iii) the remaining `valid_card_matches` / `target_filter_matches_object` users on objects that are on the battlefield or stack at evaluation. Disposition: all three classes reach the SAME typed arm, and none of their `valid_card` filters names a graveyard or library (walk W: 0 of the 78 `Sacrificed`/`Typed{You}` triggers carry `InZone` or `InAnyZone`; 0 `Destroyed`-mode triggers exist), so every one is unlicensed and keeps the single comparison. A trigger filter that does name the zone ("from your graveyard") is exactly the class the collapse is for. That list is the scope of the hostile rows V14 to V16.

Known boundary, not fixed here (verdict, claims ledger): destination-phrased triggers such as Angelic Renewal's "Whenever a creature is put into your graveyard from the battlefield" are lowered to `valid_card: Typed{Creature, controller You}` with `origin Battlefield`, i.e. to the battlefield-controller axis, so (5a) leaves them firing only for the observer's own creatures. Re-expressing them needs a parser change (out of charter); none of the 23 Dandan-list names has such a trigger (measured, see ledger).

CR annotations written: CR 400.1 (modified by the format's shared-zone axis, per the announcement), CR 400.3, CR 404.1, CR 108.4a + CR 109.5. Each grepped; no other number.

### 3.2 Unit B: count dedup with the three arms' reads (game/quantity.rs)

Dedup key and keyed population, modelled on `topology::shared_resource_dedup_key` + `players::aggregate_over_teams` (both exist: `grep -n "fn shared_resource_dedup_key\|fn aggregate_over_teams"` over `topology.rs` and `players.rs` returns one hit each; both stay read-only, and the key type is `PlayerId`, so no signature in them changes):

```text
fn zone_dedup_key(state, zone: Option<Zone>, player: PlayerId) -> PlayerId   // zone.map_or(player, |z| state.zone_storage_seat(z, player))
fn distinct_zone_holders<'a>(state, zone: Option<Zone>, players: impl IntoIterator<Item = &'a Player>) -> impl Iterator<Item = &'a Player>   // first-seen per key
```
`aggregate_over_teams` needs its own fold because its scalar is team-level; here only the population changes while the scalar stays a per-player extractor, so the keyed fold is `aggregate_over_players(distinct_zone_holders(..), aggregate, extract)` with no new fold function. `None` is the identity key (a scalar the player holds itself); `Some(zone)` is a container read.

Edits, all in `quantity.rs` (each arm's accessor read and its key are one edit):
1. `scoped_zone_holders(state, zone: &ZoneRef, scope, ctx, controller)`: `distinct_zone_holders(state, Some(zone.zone()), scoped_players(..))`. `ZoneRef::zone()` is the existing single mapping (read at `types/ability.rs`). Hand and Exile resolve to identity (Hand is per seat: `zone_storage_seat(Zone::Hand, s) == s` by Phase 6 3.1; Exile never reaches it).
2. `visit_characteristic_leaf`, `CardTypeSetSource::Zone` Graveyard/Library/Hand arm: `for player in scoped_zone_holders(..)` and the container read becomes `state.graveyard_of(player.id)` / `state.library_of(player.id)` / `&player.hand` (a small private `zone_container(state, zone, player)` shared with the next arm, so the three-way match exists once).
3. `QuantityRef::ZoneCardCount`, per-player zones arm: the same `scoped_zone_holders` and `zone_container`. The Exile arm is untouched (it already predicates per object, so it counts the object once).
4. `QuantityRef::GraveyardSize`: today `resolve_per_player_scalar(.., |p| p.graveyard.len())`. `resolve_per_player_scalar` keeps its signature as a one-line wrapper over `resolve_per_zone_scalar(state, zone: Option<Zone>, scope, ..)`, whose `Opponent` and `AllPlayers` arms fold `aggregate_over_players(distinct_zone_holders(state, zone, population), ..)`; the single-player scopes are unchanged. The arm calls the `Some(Zone::Graveyard)` form with extractor `|p| usize_to_i32_saturating(state.graveyard_of(p.id).len())`. The ~14 other callers of `resolve_per_player_scalar` are untouched (identity key).
5. `resolve_player_count`, `PlayerFilter::PlayerAttribute` arm (this is Phase 8's "all-seats count is Phase 10's dedup axis"; the parser lowers "for each graveyard with seven or more cards in it" to a count of players whose graveyard has seven, which on a shared graveyard visits one pile once per seat): a `BTreeSet<PlayerId>` declared before the `.filter(..)` chain, and the arm ends `&& counted.insert(zone_dedup_key(state, player_attribute_container_zone(attr), p.id))`, so the key is inserted only for a candidate that already passed `relation` and the comparison (relation `Opponent` over a two-seat shared pile still counts the pile once). `player_attribute_container_zone(attr: &QuantityRef) -> Option<Zone>` is `GraveyardSize{..} => Some(Zone::Graveyard), _ => None`; the wildcard mirrors `candidate_player_scalar`'s closed scalar subset (every other attribute is a per-player scalar with the identity key).
6. Not edited, with reason: `effects/mod.rs::matches_player_scope` (the other `PlayerAttribute` copy) selects the players who each ACT ("each player whose graveyard has seven or more cards, that player mills"); both seats satisfy the text and both act, so visiting seats there is correct, not a double count. `object_count_matching_candidate_ids` and `ObjectCount` stay raw and id-deduped (brief). The per-player journals (`SpellsCastThisTurn`, `PlayerCounter`) are not zone containers.

Observability of the dedup per arm (stated so no row claims more than it can show): the `CardTypeSetSource` consumers (`DistinctCardTypes`, `DistinctSubtypes`, `DistinctColorsAmong` into a `HashSet`; `Aggregate` through `seen.insert(member)`) already dedup by member or by set, so the key does not change any result for that arm; the shared helper keeps the three arms on one population authority, and the arm's discriminating row is the accessor conversion. `ZoneCardCount` with scope All (a sum) and the `PlayerCount` over a graveyard scalar are the two places where the key changes a result at a real card; `GraveyardSize` under `Max`/`Min` aggregates is key-insensitive (equal values) and under `Sum` (no supported card) is covered only by the building-block unit row.

CR annotations: CR 400.1 (shared-zone modification), CR 404.1, CR 109.5; each grepped.
