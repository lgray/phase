## Blocking

### F1 [behavior] The `obj.zone`-keyed collapse also fires for live-object evaluations of an object that has already moved to the shared graveyard, so every "you control" observer of a sacrifice or destruction starts matching the opponent's permanents

Plan 3.1 edit 1 keys `zone_axis_admits` on `obj.zone` inside the typed-filter controller arm of `filter_inner_for_object`, and edit 2 keys the live `Owned` arm on `obj.zone`. Edit 4(a) protects only the RECORD typed-controller axis (`zone_change_filter_inner`). The plan never enumerates the live callers that evaluate a typed filter against an object whose zone is already Graveyard and whose controller axis is a claim about WHO CONTROLLED IT, not "whose graveyard".

Measured by reading `trigger_matchers.rs`:
- `match_sacrificed` (about line 2714) opens with `valid_card_matches_with_lki(trigger, state, *object_id, ..)`, which calls `subject_filter_matches_with_lki`, whose first step is the live `target_filter_matches_object` -> `matches_target_filter`. Its own comment says "The sacrificed permanent may already be in the graveyard". The helper's doc says "a printed card keeps its `core_types` and `controller` across a zone change, and `filter_inner` has no zone gate".
- `match_destroyed` (about line 2760) is `valid_card_matches(trigger, state, *object_id, ..)`, a bare live match on the destroyed object, already in the graveyard.
- `effective_controller` (`filter.rs:1512`) reads the LKI controller for any non-battlefield, non-stack object under `ControllerLookup::LiveOrLki`; the plain `matches_target_filter` entry uses `LiveOrLki` (`filter.rs:4285`), so these callers reach the typed-controller arm with an object in `Zone::Graveyard`.

Failure scenario (Dandan, both seats): P0 controls a card with a "Whenever you sacrifice a permanent" trigger (`valid_card: Typed{controller: You}`; a python walk of `card-data.json` x `coverage-data.json` finds 79 supported cards with a `Sacrificed` trigger whose `valid_card` is `Typed{controller: You}`, e.g. Bloodbriar, Body Dropper, Blood Aspirant). P1 sacrifices a permanent; it lands in the shared graveyard; `match_sacrificed` evaluates the live object with `obj.zone == Graveyard`; `zone_axis_admits` tries seat P0, `You` is satisfied by P0's own seat, and P0's trigger fires on P1's sacrifice. At HEAD (and in every non-shared format after the change) it correctly does not. This is a regression in the class the collapse is not meant to touch, and no row in V1 to V13 sees it (the Phase 6/8 suites assert pile cards owned by the acting seat; the collapse only widens).

The same live path serves the `Owned` arm for any `Owned{You}` observer filter evaluated post-move.

Required revision (design, replaces the `obj.zone` key; scope unchanged, both edits stay in `filter.rs`):
1. The zone that licenses the collapse is the zone the FILTER claims, not the zone the object happens to be in. Key `zone_axis_admits` on the zone the typed filter itself pins: `FilterProp::InZone { zone }` among the same `TypedFilter`'s `properties` (Mystic Sanctuary, Haunted Fengraf, Disposal Mummy and every "your/an opponent's graveyard or library" card parse with it; measured in plan 0 and by my python walk: Mystic Sanctuary `InZone Graveyard`, Haunted Fengraf `InZone Graveyard` + `Owned{You}`, Disposal Mummy `InZone Graveyard` + `Owned{Opponent}`), or, for the zone-scoped entry, the explicit `zone` argument of `matches_target_filter_for_zone`. A sacrifice or destroy observer has no `InZone` and keeps the single comparison.
2. The `Owned` live arm has the same `InZone` property available on the same `TypedFilter` (it is evaluated inside `matches_filter_prop` with the sibling properties); the plan must say how the arm sees it (for example, `zone_axis_admits` is applied by the typed-filter loop, which knows `properties`, rather than inside the isolated prop arm) and keep the record arm keyed on `record.from_zone`.
3. Add hostile rows to V4 and the integration file: in Dandan, P0 controls a real "Whenever you sacrifice a permanent" card (the executor reads the Oracle text from card-data), P1 sacrifices a permanent: the observer does NOT fire; paired positive: P0's own sacrifice fires it (reach); the same for a `Destroyed` `valid_card: Typed{controller: You}` observer. Revert-failing leg: restore the `obj.zone` key and the P1 leg fires.
4. State in 3.1 which live callers can reach a graveyard object under `LiveOrLki` (the two above plus `target_filter_matches_object` users) and their disposition, by the command `rg -n "valid_card_matches|target_filter_matches_object|matches_target_filter\(" crates/engine/src/game/trigger_matchers.rs`; that list is the scope of the hostile rows.

Item 3.1 edit 3 (no edit to `matches_target_filter_in_owner_zone`) survives: the explicit-zone entry carries the zone, so with the revised key the owner-zone path still collapses through the typed arm.
