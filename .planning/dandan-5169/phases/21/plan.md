# Phase 21 plan (r0) — S9a host-supplied Dandan pile, engine half (PHASE_BASE_SHA a10c2316ddf3e9b6090b6c81d734d6b5375d8c76)

Task (PR #9669, USER scope addition): the Secret Lair 80 stays the default; a host may supply a different 80-card pile. Validation = exactly 80 cards, every name resolvable, no ban list, no copy limit (the CR 407.3 ante refusal stays). One pile per game, chosen at lobby level, the same path for AI, P2P, native and server games and for replay. Engine decides and validates; the client (Phase 22, not this plan) only displays and dispatches. Charter fork: choice INSIDE Dandan, the pile rides as the pile seat's submitted `main_deck` (`GameState::canonical_seat()`), an empty submission falls back to the default list, typed axis `GameFormat::deck_supply()`, wasm export `deck_supply_for_format`, `validate_deck_for_format` the single validation authority.

## Shape of the code (module headers + one entry-point trace; no stated architecture file exists beyond the doc comments)

Parts and owners: the **loader** `deck_loading.rs::load_and_hydrate_decks` is the one authority that turns a submitted `DeckPayload` into libraries and deck pools, and is called by wasm `initialize_game_impl` (both local and multiplayer-host kinds), `server-core::GameSession::start_game`, and `replay::reconstruct_initial_state`; the **validator** `validate_deck_for_format` (via `validate_name_deck_for_format_full` and the P2P guest gate `evaluate_deck_format_gate`) is the one admission decision, called at the wasm seat loop `validate_deck_list_seats`, the phase-server create handler and `ai_seat_setups`; the **format axes** on `GameFormat` (`types/format.rs`) are the only place that answers format questions; transports serialize. Trace driven at base (probe tree = `rsync` of W, built under a scratch target): an 80-card pile submitted on seat 0 of a Dandan state is replaced by the default 23-name list in `dandan_fixed_deck_payload`, and the pool registered afterwards is the default's (23 entries).

## Step 0: card text and the default list (verbatim, `jq` over `client/public/card-data.json`)

Each of the 23 names in `DANDAN_DECKLIST` resolves with identical spelling (`jq 'has($n)'` per lowercased name; "Dandân", "The Surgical Bay", "Svyelunite Temple", "Day's Undoing" included) and the multiplicities sum to 80 (10+20+8+4+19x2). Dandân: "This creature can't attack unless defending player controls an Island. When you control no Islands, sacrifice this creature." No other card's behaviour is touched. Fixture-resolvable names for the tests (all `true` in `integration_cards.json.gz`): Forest, Swamp, Mountain, Lightning Bolt, Bloodbraid Elf, Hymn to Tourach, Black Lotus (Legacy-banned, Vintage-restricted), Amulet of Quoz (carries "Remove this card from your deck before playing if you're not playing for ante").

CR (grepped in `docs/MagicCompRules.txt`, subject = the claim): 407.3 "When not playing for ante, players can't include these cards in their decks or sideboards" (the ante refusal the pile keeps); 103.3 "each player shuffles their deck ... The players' decks become their libraries" (the pile becomes the library). The "no ban list / no copy limit" rule is the format's own announcement, not a CR rule; no CR is cited for it.

## Decision

1. **Typed axis.** `pub enum DeckSupply { PlayerBuilt, EngineFixed, HostPile }` (`Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize`) and `GameFormat::deck_supply(self) -> DeckSupply`, exhaustive with no wildcard arm (Momir `EngineFixed`, Dandan `HostPile`, every other built-in and `Custom(_)` `PlayerBuilt`), in `types/format.rs` beside the arm list `supplies_fixed_deck` holds today. `supplies_fixed_deck()` becomes `self.deck_supply() != DeckSupply::PlayerBuilt` (value unchanged for every format), so `FormatConfig.supplies_fixed_deck` and the registry stay one source. No serialized shape changes: `DeckSupply` is never a field of a serialized type; it is only the return of the wasm export.
2. **Loader.** `dandan_fixed_deck_payload` becomes `dandan_pile_payload`: for the pile seat (`state.canonical_seat()`) it takes `payload_for_player(submitted, pile_seat).main_deck` when non-empty, else the default names resolved as today, and builds the seat through one `main_deck_only_payload(Vec<DeckEntry>)` (`fixed_seat_payload` becomes `main_deck_only_payload(resolve_names(..))`), so a submitted sideboard, commander or other slot never loads; every other seat gets `PlayerDeckPayload::default()` as today. `dandan_fixed_deck_names`/`DANDAN_DECKLIST` are renamed `dandan_default_pile_names`/`DANDAN_DEFAULT_PILE` (the word "fixed" is false afterwards; two consumers). Replay needs no change: `ReplayHeader.deck_data` already stores the submitted `DeckList` and `reconstruct_initial_state` calls the same loader.
3. **Validator.** In `validate_deck_for_format`, after the existing unresolvable-Custom guard, a request whose every card slot is empty (`DeckCompatibilityRequest::is_empty_submission`: main, sideboard, commander, companion, planar, scheme, signature) for a selected format whose `tag().deck_supply()` is not `PlayerBuilt` is `Ok(())`. Anything else falls through to the existing chain unchanged: for Dandan that is `evaluate_constructed` (exactly 80 via `DeckSizeRule::Exactly(80)`, no sideboard, no commander slot, `DeckCopyLimit::Unlimited`, `CardPool::NoEngineAuthority` admits every card, unknown names refused) plus the format-independent `ante_deck_violations` (CR 407.3). No seat concept is added. Momir's empty submission becomes accepted; a non-empty Momir list is still checked by `quick_momir_check`/`evaluate_momir`.
4. **wasm boundary.** `validate_deck_list_seats` drops the `supplies_fixed_deck` skip and calls the authority for every seat (player, opponent, each AI seat), the two duplicate loops collapsing into one over `(label, deck)` pairs with the same first-refusal short-circuit and labels. New `#[wasm_bindgen(js_name = deckSupplyForFormat)] pub fn deck_supply_for_format(format: JsValue) -> JsValue` beside `bestOfThreeCeilingForFormat`, backed by a pure `deck_supply_or_player_built(Option<GameFormat>)` (undecodable format answers `PlayerBuilt`: the client then asks for a deck, the safe default). `client/src/wasm/engine_wasm.d.ts` is regenerated by `./scripts/build-wasm.sh wasm-dev`, never hand-edited; the diff must be one added declaration.
5. **Server legs: no production change.** The create handler's host check and `ai_seat_setups` both call `validate_name_deck_for_format_full`, so Decision 3 alone makes an empty host deck and an empty AI-seat `DeckList` pass (claim 4, driven rows below). The `deck: None` / `deckName` AI shape is dropped with a stated verdict: no sender reaches it for a supplying format (`ws-adapter.ts` builds both setup frames with an explicit `DeckList`; Dandan and Momir are `max_players == 2`, and a lobby host whose only opponent is an AI seat routes to the local AI path in `executeAction` before any `ai_seats` frame), so a server-side override would serve no input. The P2P guest gate (`evaluate_deck_format_gate`) is fixed by Decision 3 alone.
6. **Rejected.** Dispatching the loader on `deck_supply()` (the fixed lists are per format, so an `EngineFixed => momir_*` arm would be the same literal dispatch in disguise); a seat parameter on the validator (charter); a Dandan-specific validator function; Custom-format exposure (charter).

Ladder (three lines). Task: let the host's 80 names reach the shared library, and let an empty submission mean "use the default" at every boundary that admits decks. By hand: change the one loader branch to read the pile seat's submission and make the one validator accept empty for supplying formats. Rung 2 holds: the loader branch, `payload_for_player`, `fixed_seat_payload`, `validate_deck_for_format` and the Momir skip all exist, and the axis is the repository's own pattern for format questions (rung 1 fails: base red rows; rung 3-4 have no tool for it).
