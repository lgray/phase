## Verdict: REVISE (4 blocking behavior findings, 1 scope decision, 3 blocking text findings)

The primitive's core design is sound and I would keep it: a Layer-3 pre-gather pass is the right seam for permanents (the main loop gathers every Layer 4-7 effect once, right after layer 1, so a text change applied inside the Text bucket would be too late for Bad Moon; Layer 1 already has its own pre-pass for the same reason), and the `snapshot_transient_modifications` latch plus the existing `Choose(Labeled)` round trip are the right seams for the word choice. The defects are in what the plan leaves uncovered around those seams.

## Blocking findings

### F1 [behavior] A second layer evaluator exists and the plan never names it
`apply_layers_incremental` / `prepare_incremental_flush` (`game/layers.rs`) re-derive recipient objects on their own Step 3-4 loop, fed by `collect_shared_active_continuous_effects` -> `bucket_effects_by_layer`. The plan adds the Text pre-pass and the "remove from the Text bucket" filter only in `evaluate_layers`. Consequence: an object that enters while a live `SubstituteTextWord{Fixed}` names it is reset to base (`reset_recipient_to_base`) and the variant's apply arm is a documented no-op, so the text change is absent until the next full pass. This is reachable by the plan's own cards: Magical Hack on a permanent spell (Bog Wraith on the stack) resolves, the creature enters through the incremental path, and Plainswalk is missing. The existing escalation guard only covers a recipient whose live zone is the stack, and at flush time the entrant is already on the battlefield. `CharacteristicKinds::ALL` (plan 3.6) does not help: it governs perturbation by an entrant, not whether the recipient's own live effect is applied.
Required revision: (a) name `apply_layers_incremental`, `prepare_incremental_flush`, `bucket_effects_by_layer` (the shared place a `SubstituteTextWord` filter must live, since the filter cannot go inside `gather_transient_continuous_effects`, which the pre-pass itself calls); (b) choose one of: escalate to the full pass (`return None` in `prepare_incremental_flush`) whenever any live `SubstituteTextWord{Fixed}` TCE names an entrant, or run the same pre-pass restricted to `recipient_ids`; (c) add to L1 an entrant case (board with a live substitution, an entrant that is its recipient, incremental result == forced-Full result), and a resolution-entry row (see F2). Needs probe: the L1 entrant case is the probe.

### F2 [behavior] Plan asserts "no claim" about CR 400.7a, but the engine already carries grants across stack->battlefield
`game/zones.rs::prune_object_bound_effects_on_exit` returns early for `from == Stack && to == Battlefield` ("CR 400.7a, its grants continue to apply to the permanent that spell becomes"), so a TCE with `SpecificObject{spell id}` survives onto the permanent. The plan (sections 1 and 13) says the engine deviates for all grants and makes no claim; the code contradicts the premise (the comment quoted from `effect.rs` ("Today such grants are instead pruned at cleanup") is stale relative to `zones.rs`). With the pre-pass, a Hack on a permanent spell therefore changes the resulting permanent (CR 400.7a-correct, grepped: "Effects from spells, activated abilities, and triggered abilities that change the characteristics or controller of a permanent spell on the stack continue to apply to the permanent that spell becomes"). The plan must claim and test it, and test the opposite leg.
Required revision: replace the "no claim" sentences with the measured behavior and add rows: S3 = Magical Hack `"Swamp -> Plains"` on a Bog Wraith spell on the stack; after resolution the permanent has `Landwalk("Plains")` (revert-fails: drop the pre-pass or the incremental handling of F1); S4 = a text change on a non-permanent spell is pruned when it leaves the stack (TCE list empty after resolution), with a positive guard that S3's TCE is present while the permanent lives.

### F3 [behavior] The stack-spell rewrite covers two fields of `ResolvedAbility`; the struct carries more text-derived fields
Plan 3.3(b) rewrites "the ability chain's `effect` and `condition` fields (recursing `sub_ability`, `else_ability`, `mode_abilities`)". Measured `ResolvedAbility` fields (types/ability.rs struct body) that hold typed filters/quantities derived from Oracle text: `repeat_for: Option<QuantityExpr>`, `optional_player: Option<TargetFilter>`, `player_scope: Option<PlayerFilter>`, `unless_pay`, `multi_target: Option<MultiTargetSpec>`, `target_constraints`, `duration`, `announced_x`. A color or land word in any of these (a "for each black creature" repeat, a scoped-player filter) is left unchanged, so the resolving spell reads half-changed text, which is exactly the half-state CR 612.1 forbids. Also `mode_abilities` is a field of `AbilityDefinition` (types/ability.rs), not of `ResolvedAbility`; a chosen mode is already flattened into `sub_ability` at cast.
Required revision: state the rewrite as a field-exhaustive destructure of `ResolvedAbility` (no `..`), each field classified TextBearing (rewritten by the same `TextSubstitution::rewrite` authority) or RuntimeState (with the reason), so a future field forces a decision; drop `mode_abilities` from the recursion list. Add a matrix row where the changed word sits in one non-`effect` text-bearing field, using a real card located by a census over the corpus by field (command named in the plan; I assert no card here). Needs probe: P-F below.

### F4 [behavior] Row P2 (the charter's CR 612.2 hostile fixture) cannot fail
P2 asserts the object name is unchanged after a substitution and claims "table row flipped to Word -> name assertion red". The object's name is never in the rewritten set (`apply_to_permanent_text` excludes `obj.name` by construction, plan 3.3(a)) and `Token.name` is a different carrier, so the assertion passes under any carrier-table error. The charter says this claim is bought by a hostile fixture, not by reading the resolver. Row P5's Llanowar Elves case is genuinely discriminating (it flips with the mana-production row) but has no Word carrier on the same card to prove the instrument fired.
Required revision: replace the P2 revert claim and make the same-card hostile the charter fixture: Dromoka Monument (verbatim: "{T}: Add {G} or {W}." / "{4}{G}{W}: This artifact becomes a 4/4 green and white Dragon artifact creature with flying until end of turn."), Sleight of Mind `"Green -> Blue"`: the mana ability still produces G or W (NotAWord) and the animation's color set becomes blue and white after activation (Word). Revert-fails: flip the mana-production row to Word (mana changes) or drop the `SetColor` row (animation stays green). Keep Mountain Goat/name assertions only as a non-discriminating note, not as a revert-fails row. Also add the missing CR 612.3 row the plan's own section 1 relies on: a Merfolk without islandwalk under Lord of Atlantis ("Other Merfolk get +1/+1 and have islandwalk.") keeps `Landwalk("Island")` after Magical Hack `"Island -> Forest"` targets that Merfolk (granted, not text), paired with Hack on Lord itself granting forestwalk (printed text), so the row can only pass if Layer 6 runs after the pre-pass.

### F6 [text] Gather/pre-pass wording and the parity test list
(a) Section 3.3(a) says the effects are "removed from the `Layer::Text` bucket of the main gather". Replace with: "filtered out in `bucket_effects_by_layer`, the one bucketing authority both the full pass and the incremental flush use, so neither evaluator applies them twice; the pre-pass gathers them itself through `gather_transient_continuous_effects`." ### F7 [behavior, low] Latch reads `state.last_named_choice` with no consumption check
`snapshot_transient_modifications` would latch whatever `Label` is in `last_named_choice`; `from_label` succeeds for any previously chosen pair inside the domain list, so a skipped or auto-resolved `Choose` would latch a stale earlier answer (measured: `last_named_choice` is cleared only in a few unrelated paths, e.g. `choose_counter_kind.rs`, `engine_resolution_choices.rs`). Require the latch arm to take (`.take()`-style clear of) the value it consumed, plus a hostile in C1: two sequential Spectral Shift modes (Entwine) each latch their own answer (mode 1 land pair, mode 2 color pair), proving no cross-read. Fold into the same revision as F1-F4; not separately blocking if the C1 row is added.
