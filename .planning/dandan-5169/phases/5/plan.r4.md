## 1. CR 612 reading (greps of `docs/MagicCompRules.txt`, all MEASURED)

- 612.1: text-changing effects change words on the object, generally rules text and type line. 613.1c: Layer 3.
- 612.2: only words "used in the correct way" change; a color word used as a color word, a land type used as a land type. A color-word/subtype change can't change a card name even if the name contains the word.
- 612.2a: token-creating text's creature types double as names and ARE changed (creature-type domain only; not reached here).
- 612.3: granted abilities are not text, so they are not changed (Layer 6 runs after Layer 3).
- 612.4: a token's subtypes and rules text are defined by its creating spell/ability and are changeable.
- 608.2b: target legality is rechecked on resolution, and "an effect may have changed the text of the spell" is named there.
- 608.2d: choices an effect offers are made as it resolves (the words are chosen on resolution, not at cast).
- 611.2a: no stated duration means until end of game. 611.2c: the affected set is fixed when the effect begins.
- 613.7b: resolution-generated effects take a timestamp when created; 613.7: timestamp order within a layer.
- 305.6/305.7: basic land types; a basic land type grants an intrinsic mana ability. 205.3i: land types.
- 105.1: five colors. 702.14a: landwalk "[type]walk".
- 400.7a: effects from spells that change characteristics of a permanent spell continue onto the permanent (grepped). MEASURED (`game/zones.rs::prune_object_bound_effects_on_exit`): the engine returns early for `from == Stack && to == Battlefield`, so a transient effect bound to a spell's `SpecificObject` id survives onto the permanent, and is pruned on every other exit (`prune_affected_object_left_effects`). The stale "KNOWN DEVIATION (task #129)" comment in `effect.rs` is therefore not the behavior. Consequence, claimed and tested here: a Magical Hack on a permanent spell changes the permanent it becomes (rows S3), and a text change on a non-permanent spell is gone once the spell leaves the stack (S4).

### 1.1 What "word" means (the contract the whole design rests on)
A value is a text word iff the Oracle phrase that produced it renders that value as a color word ("black") or a land-type word ("Forest", "forestwalk"). A mana symbol ({B}), a card name, an option label, a mana-cost shard are NOT words (CR 612.2). Consequence: `ManaColor` and land-type strings are both words in some carriers and not words in others, so the substitution is **carrier-directed**, never a blind value replace.

### 1.2 Domain
`{ColorWord, BasicLandType}` — the two words the cards in scope name. Five colors (CR 105.1) and five basic land types (CR 305.6) are closed sets, so the choice is a finite enumerable prompt.

### 1.3 Why creature types and the other members stay OUT (CR 612 reasoning)
CR 612 treats creature type words identically, so the primitive is built to take them as one more leaf, but the members cannot ride this phase honestly: (a) the charter fixes the domain at `{BasicLandType, ColorWord}` and the brief calls creature type "the class's next member"; (b) the creature-type domain is an open string set (CR 205.3m registry, `ChoiceType::CreatureType` already exists) with Artificial Evolution's "can't be Wall" restriction and New Blood's fixed target word and gain-control, each needing its own restriction/parse path; (c) CR 612.2a makes token names follow creature-type changes, a carrier rule that does not exist for the two domains here and would be untested. Magical Hacker swaps mana-ability symbols ("+", "-"), which are not one of the typed word domains. Deceptive Divination replaces a card-type word on objects not on the stack (a plane, different population and domain). Exchange of Words is CR 612.5, a text-box exchange, a different primitive. All five stay `Effect::unimplemented` by construction: the new parser recognizer fails closed on any domain phrase other than "color word" / "basic land type" (a discriminating parser test, §9, pairs each with a positive sibling).

## 3. Design

### 3.1 Types (`types/ability.rs`, beside `BasicLandType`)
```
/// CR 612.2: the word classes a text-changing effect can name.
enum TextWordDomain { ColorWord, BasicLandType }
/// CR 612.2: one concrete from→to word replacement; both words are of one class.
enum TextSubstitution {
    Color { from: ManaColor, to: ManaColor },
    BasicLandType { from: BasicLandType, to: BasicLandType },
}
/// Fixed = latched words (what the layer applies). Chosen = parse-time form,
/// words picked on resolution (CR 608.2d), latched to Fixed when the effect installs.
enum TextSubstitutionSpec { Fixed(TextSubstitution), Chosen { domains: Vec<TextWordDomain> } }
ContinuousModification::SubstituteTextWord { substitution: TextSubstitutionSpec }   // layer(): Layer::Text
```
Methods on `TextSubstitution` (single authority for label round trip; no duplicated option lists): `options(domains: &[TextWordDomain]) -> Vec<String>` (every ordered pair with `from != to`, domain order then WUBRG×WUBRG / Plains…Forest order), `label(&self) -> String` (`"Black -> Blue"`, `"Forest -> Island"`), `from_label(label, domains) -> Option<Self>` (rejects `from == to` and any label outside `domains`). "It can't change a word to the same word" (ruling) holds by construction; the rules let the player name words absent from the object (ruling "can target a card with no appropriate words"), so options are NOT narrowed to words present. The choice is one atomic prompt because both words are chosen at the same resolution point (CR 608.2d); a pair prompt also makes "from ≠ to" structural, and Crystal Spray's domain pick is folded into the same pair list (20 color pairs + 20 land pairs, unambiguous labels).

Why `Fixed|Chosen` inside one variant and not `SubstituteTextWord` + `SubstituteChosenTextWord`: the codebase's Dynamic/Fixed pairs (`AddDynamicPower` → `AddPower`) are siblings of the same name root; parameterizing avoids a third cluster. A `Chosen` modification reaching the layer is inert (never applied); `snapshot_transient_modifications` (the existing latch seam, `game/effects/effect.rs`) converts Chosen → Fixed.

### 3.2 Emitted ability shape (parser output, all existing variants)
Precedent (MEASURED): Chaoslace card-data = `GenericEffect { static_abilities: [continuous, affected: ParentTarget, [SetColor]], duration: Permanent, target: Or[StackSpell, Typed Permanent] }`; `try_parse_become_choice` emits `Choose → sub_ability GenericEffect`.
Output for "Change the text of <target> by replacing all instances of one <domain> with another [or one <domain> with another] [until end of turn]":
```
Choose { choice_type: Labeled { options: TextSubstitution::options(domains) }, persist: false, selection: Chosen }
  └ sub_ability: GenericEffect {
        static_abilities: [ continuous().affected(ParentTarget)
                            .modifications([SubstituteTextWord{ Chosen{domains} }]).description(clause text) ],
        duration: Some(Permanent | UntilEndOfTurn),
        target: Some(<parsed target filter>), end_cost: None }
        └ sub_ability: (Crystal Spray only) Draw 1 — produced by the normal chain assembler from "Draw a card."
```
Duration: no stated duration ⇒ `Duration::Permanent` (CR 611.2a), set explicitly by the recognizer because `effect.rs` defaults `None` to EOT (the documented known deviation). "until end of turn" ⇒ `UntilEndOfTurn`.

### 3.3 Where the substitution is applied (consumption seams)
One authority decides which words apply to which object: `text_substitution::active_text_substitutions(state) -> BTreeMap<ObjectId, Vec<TextSubstitution>>`. It gathers with `gather_transient_continuous_effects`, keeps only effects whose layer is `Layer::Text`, whose modification is `SubstituteTextWord{Fixed}` and whose `affected` is `TargetFilter::SpecificObject` (every parser-produced instance is one, via `ParentTarget`; a filter-shaped recipient set is deliberately not consumed, because the pre-pass runs before the Layer-2 bucket and such a set could depend on controller, CR 613.1 layer 2 precedes layer 3), groups them per recipient FIRST (`BTreeMap<ObjectId, Vec<ActiveContinuousEffect>>`, keyed by the `SpecificObject` id) and only then orders each recipient's list with its own call `order_active_continuous_effects(Layer::Text, …)` (dependency first, then timestamp; see the CR 613.8 paragraph below), so no ordering bucket ever holds effects of two recipients. Both consumers below call only this function, so a permanent and a spell read the same effect list. **CR 613.8 dependency ordering in Layer::Text (N2; greps of `docs/MagicCompRules.txt` lines 3042-3048, MEASURED).** CR 613.8: within a layer a dependency "will override the timestamp system". CR 613.8a: effect A depends on effect B iff both apply in the same layer and applying B "would change the text or the existence of the first effect, what it applies to, or what it does to any of the things it applies to" (neither or both from CDAs; text effects here are never CDAs). CR 613.8b: a dependent effect applies just after all effects it depends on; a dependency loop is applied in timestamp order. CR 613.8c: the order is re-evaluated after each application. `Layer::Text.has_dependency_ordering()` is true (`types/layers.rs`), so `order_active_continuous_effects` runs `order_with_dependencies`, whose `depends_on` (`game/layers.rs`, shape-based, payload-only, state-blind by its own documented contract) has no arm for the new variant; without one the variant would silently fall back to timestamp, which the rules forbid for a chain. The reading for two `SubstituteTextWord{Fixed}` effects of ONE domain: A = (a.from -> a.to) depends on B = (b.from -> b.to) iff `b.to == a.from` (applying B creates the word A acts on, so B changes what A does to the object) or `b.from == a.from` (applying B removes the word A acts on; this edge is symmetric, so the pair forms a CR 613.8b loop and is applied in timestamp order). Effects of different domains (Color vs BasicLandType) never depend on each other: a color word and a land-type word are disjoint carriers (CR 612.2). The predicate reads only the two modification payloads, so it is invariant across the pass, preserving `depends_on`'s contract that a state-aware predicate would require the CR 613.8c re-evaluation fix. The same-source/same-transient suppression at the top of `depends_on` is unaffected (two Hacks have distinct transient ids). **Recipient scoping (R3-1) and the whole-bucket cycle fallback (S3-1).** MEASURED (read `game/layers.rs` 7766-7839, `order_with_dependencies`): on ANY cycle the function returns the WHOLE bucket in timestamp order (its own comment, lines 7820-7828, records this as a coarser-than-CR-613.8b tracked deviation). Two defects follow if the edge were recipient-blind or the bucket mixed recipients: two same-`from` effects on an unrelated object form a 2-cycle and revert the chain on another object to timestamp order. CR 613.8a(b) asks whether applying the other effect changes "what it does to any of the things it applies to"; for a text effect those things are the one recipient's words, so an effect on Y cannot change what an effect on X does. Three measures, all required: (1) the `SubstituteTextWord` arm of `depends_on` first requires BOTH `affected_filter`s to be `TargetFilter::SpecificObject { id }` with the SAME id and returns false otherwise (a non-`SpecificObject` recipient never depends, and `Chosen` specs never depend, by exhaustive match); only then the domain / `b.to == a.from` / `b.from == a.from` rule; the arm sits directly after the same-source suppression and returns for any pair where both are `SubstituteTextWord` (a mixed pair, `SubstituteTextWord` vs another kind, falls to the existing arms, none of which can fire because the recipient is a `SpecificObject`; in practice no mixed pair exists: `bucket_effects_by_layer` removes every `SubstituteTextWord` from the main Text bucket, and the pre-pass gathers only `SubstituteTextWord{Fixed}`; `SetTextName`/`SetChosenName` rewrite the name, `SubstituteTextWord` never touches the name (CR 612.2), so the two kinds are disjoint carriers and their relative order is unobservable, hence independent under CR 613.8a); (2) `active_text_substitutions` groups per recipient before ordering, so a cycle on Y is confined to Y's own call and cannot reorder X (this is the measure that defeats a same-recipient loop on another object; the guard in (1) alone does not, because Y's own same-`from` pair still cycles in a shared bucket); (3) `order_with_dependencies` implements the CR 613.8b loop-only fallback instead of the whole-bucket one (its tracked deviation), so that on ONE object a loop does not drag a non-loop chain effect back to timestamp order. Concrete reachable case for (3): three Hacks on one Bog Wraith, B=`Plains -> Forest` cast first, then A=`Swamp -> Plains`, then C=`Swamp -> Forest`. A and C form a loop (timestamp order A, C); B depends on A only (A.to == B.from) and applies just after it. CR 613.8b result: A, B, C => Forestwalk. The whole-bucket fallback gives B, A, C (B finds no Plains, A makes Plains, C finds no Swamp) => Plainswalk, wrong. Loop-only algorithm (for the executor; deterministic, n is tiny): when Kahn stalls, compute for the unprocessed nodes the strongly connected components of the remaining dependency graph; choose the source component (no dependency edge from another unprocessed component) holding the lowest sorted index (a stall guarantees every source component is a nontrivial loop, since a trivial source would have in-degree 0); remove the edges internal to that component (`dependencies[j].retain(|i| !in_component(i))` and `in_degree` lowered to match, each edge removed exactly once); resume the Kahn loop, which picks the lowest sorted index with in-degree 0, so loop members apply in timestamp order and downstream dependents wait for them. When the whole bucket is one loop, the result equals today's fallback, so the existing mutually-copying-permanents test (`mutually_copying_permanents_reach_a_layer_one_fixed_point`, its comment names the 613.8b fallback) keeps its outcome; the executor runs the layers suite and, if any pre-existing test fails for a reason other than the coarse-vs-loop-only distinction, stop-and-returns with the output. The state-blind contract of `depends_on` is untouched, so CR 613.8c stays satisfied by computing once. The same-source/same-transient suppression at the top of `depends_on` is unaffected (two Hacks have distinct transient ids; a Spectral Shift with Entwine yields two transients on one source, also distinct; its land and color modes are different domains so they never depend on each other anyway). Consequence for the plan's own chain pair (`Swamp -> Plains`, `Plains -> Forest`): the second depends on the first, so the order is Swamp->Plains then Plains->Forest (Forestwalk) in BOTH casting orders, PROVIDED both are on the same recipient (R3-1: the same pair split across two objects is independent, each object simply has one effect); the loop pair (`Swamp -> Plains`, `Swamp -> Forest`) on one object applies in timestamp order (CR 613.7b), and does so without disturbing any other object or any non-loop effect on the same object. If the executor concludes the shape-based `depends_on` must not gain this arm, that is a stop-and-return quoting CR 613.8a, never a silent timestamp result.

Readers of an object's rules text are of two kinds.

(a) **Permanents (battlefield).** New module `game/text_substitution.rs` owns `apply_to_permanent_text(obj, TextSubstitution)`. It is called from a **Layer-3 pre-gather pass** in `evaluate_layers` (`game/layers.rs`), placed after Layer 1/1b/stickers and its static-index refresh and before `gather_active_continuous_effects`. Reason: the main loop gathers every Layer 4-7 effect once from `static_definitions` before any layer applies, so a text change applied inside the Text bucket would be too late for a changed static ability ("Black creatures get +1/+1" on Bad Moon); Layer 1 has its own pre-pass for the same reason (CR 613.2). The pass visits only recipients whose zone is `Zone::Battlefield` and that are phased in (the set the reset loop resets); it bypasses `apply_continuous_effect`'s attribution/`started_effect_sets` bookkeeping (comment at the pass). `SubstituteTextWord` effects are filtered out in `bucket_effects_by_layer`, the one bucketing authority both the full pass and the incremental flush use, so neither evaluator applies them twice; the pre-pass gathers them itself through `gather_transient_continuous_effects` (filtering inside that function would be wrong: the pre-pass calls it). `ContinuousModification::layer()` still returns `Layer::Text` (charter: "evaluated at the existing text layer"); `apply_continuous_effect`'s arm for the variant is an exhaustiveness-only documented no-op, reachable by no path because of the bucket filter. Layer 6 runs later, so granted abilities are untouched (CR 612.3).

What `apply_to_permanent_text` rewrites, all of it the object's rules text or type line (CR 612.1): `obj.abilities`, `obj.trigger_definitions`, `obj.static_definitions`, `obj.replacement_definitions` (printed entries only; entries for which `ReplacementDefinition::is_resolution_installed()` are continuous effects a resolution created, not text, and are skipped, CR 612.3 spirit; `reseed_replacements_carrying_resolution_effects` shows the printed/installed split), `obj.keywords`, and the subtype list of `obj.card_types` (land-type word on the type line; result de-duplicated, since a subtype set has no repeats). The object's name, mana cost, color indicator and P/T are never touched (CR 612.2; mana symbols and cost shards are not words). The basic-land intrinsic mana ability is derived after the Type layer by `apply_intrinsic_basic_land_mana_abilities` (MEASURED in `evaluate_layers`), so a Forest whose subtype became Island taps for {U} with no extra code (CR 305.6/305.7).

**The incremental evaluator (F1).** MEASURED by reading `game/layers.rs`: `flush_layers` has a second evaluator, `prepare_incremental_flush` -> `apply_layers_incremental`, which resets only the entered objects (`reset_recipient_to_base`) and re-applies the shared effect set to them through `bucket_effects_by_layer`, never through the pre-pass. A permanent that enters while a live `SubstituteTextWord{Fixed}` names it (Magical Hack on a permanent spell, CR 400.7a, see S3) would therefore be reset to base with its text change lost until the next full pass. Decision: `prepare_incremental_flush` returns `None` (escalates to `evaluate_layers`) whenever any active `SubstituteTextWord` effect satisfies the existing `effect_can_reach_incremental_recipients(effect, &recipient_ids)`, placed beside the existing Stack-zone and Copy escalation disjuncts. The alternative (running the pre-pass restricted to `recipient_ids`) is rejected: it duplicates the pass with a second recipient-restriction path, while escalation is exact by construction and costs nothing on a board with no text change. Pre-existing permanents are never reset by the incremental arm, so their already-rewritten text persists and needs nothing. Pinned by L1 (entrant case) and S3.

(b) **Spells on the stack.** Stack objects are not reset by the layer pass (MEASURED: the stack-seed loop in `evaluate_layers` resets only `keywords` and `controller`, with a comment to extend the reset authority before a static modifies another stack characteristic), and a resolving spell reads the `ResolvedAbility` stored in its stack entry, not `obj.abilities`. So for `obj.zone != Zone::Battlefield` the layer does NOT mutate the object (a mutation would be sticky). Instead `text_substitution::restamp_resolving_spell_text(state, object_id, &mut ResolvedAbility)` is called in `resolve_top` (`game/stack.rs`) directly beside the existing "CR 608.2c re-stamp the resolving spell's baked controller" block, before `bind_resolving_ability_referents` and before the CR 608.2b legality recheck, for `is_spell` entries only (an activated/triggered ability on the stack is not a spell or permanent; CR 113.8). It looks up `active_text_substitutions(state)[object_id]` and rewrites the ability chain.

The chain rewrite is a **field-exhaustive destructure of `ResolvedAbility` with no `..`** (F3), applied to the node and recursively to `sub_ability` and `else_ability`. Every field is classified once, so a future field forces a decision at compile time. MEASURED field list: **66 fields** (`awk` over `pub struct ResolvedAbility` in `types/ability.rs`, re-run for this revision; the r1 figure of 63 and the claim that `mode_abilities` belongs only to `AbilityDefinition` were wrong: `ResolvedAbility.mode_abilities: Vec<AbilityDefinition>` exists, used by reflexive modal triggers, and the chosen-mode flattening into `sub_ability` does not empty it). Classification:

### 3.4 The rewrite engine (`game/text_substitution.rs`)
`TextSubstitution::rewrite<T: Serialize + DeserializeOwned>(&self, value: &T) -> Option<T>`: serialize to `serde_json::Value`, walk, rewrite at carrier positions only, deserialize back; `None` when nothing changed or the round trip fails (fail-closed: text unchanged). The round-trip-failure arm carries a `debug_assert!` so a census miss cannot hide in test runs (only a genuine serde failure reaches it; "nothing changed" is a separate `None` arm). Why a value walk and not a hand-written exhaustive mutable visitor: the engine has no mutable typed walker over `Effect`/filters/conditions (MEASURED: `ability_visit.rs` is an immutable `&Effect` visitor that descends abilities only; `each_target_filter_mut` in `parser/oracle_effect/mod.rs` is explicitly partial with a `_ => {}` arm), and the color/land words are spread over ~55 measured carrier positions (census below). A new exhaustive mutable walk of the AST would be a separate multi-thousand-line project; the value walk touches each carrier once.

Completeness is enforced by measurement over the corpus the tests can see, instead of by a hand-kept list being "probably right" (limit stated: CEN1/CEN2 run in CI only over the committed fixture via `shared_card_db()`; the full export run is the opt-in `FORGE_TEST_FULL_DB=1`, so table completeness for card shapes outside the fixture is not CI-enforced; an unclassified position fails closed, text unchanged): **carrier classification table** `WORD_CARRIERS` (one `const` table in this module, each row `(container tag, field, WordClass)` with `WordClass = Word(TextWordDomain) | NotAWord(reason)`), plus a **census test** (§9 row CEN1) that walks every card face in the shared card DB (`test_support::shared_card_db()`: committed fixture by default, full export under `FORGE_TEST_FULL_DB=1`), serializes `abilities/triggers/static_abilities/replacements/keywords`, and fails on any `ManaColor` or basic-land-type string whose `(container, field)` is in neither class. A new card shape that introduces a new position turns the test red and forces a Word/NotAWord decision. Round-trip identity (`from_value(to_value(x)) == x`) is asserted over the same corpus (row CEN2). MEASURED support: `types/ability.rs` contains no `#[serde(skip)]` field (grep), and card-data itself is the serialized form the engine loads.

### 3.5 Choice latch (`game/effects/effect.rs`, `register_transient_effect`)
A new function `latch_chosen_text_words(state: &mut GameState, modifications: Vec<ContinuousModification>) -> Vec<ContinuousModification>` runs in `register_transient_effect` immediately after `snapshot_transient_modifications` (`state` is `&mut` there; the snapshot function itself takes `&GameState` and is left untouched). It is a no-op unless a `SubstituteTextWord{Chosen{domains}}` is present. When present it **takes** `state.last_named_choice` (`Option::take`, so the answer is consumed exactly once, F7): if the taken value is `ChoiceValue::Label(l)` and `TextSubstitution::from_label(&l, &domains)` succeeds, the modification becomes `SubstituteTextWord{Fixed(sub)}`; otherwise the `Chosen` form stays (inert, nothing applies, fail-closed) and the choice is still consumed. This is the `AddDynamicPower` latch pattern (CR 608.2h: information fixed when the effect is applied; CR 611.2c). The prompt is answered through the existing `WaitingFor::NamedChoice` / `GameAction::ChooseOption`; `bind_named_choice` with `persist: false` stores `last_named_choice = Label(..)` (MEASURED: `ChoiceValue::from_choice` maps `Labeled` to `Label`; `effects/choose.rs` sets `last_named_choice` at the two `from_choice` sites). The player answering is the spell's controller (CR 608.2d). Why take: `from_label` succeeds for any earlier pair inside the domain list, and `last_named_choice` is cleared only in unrelated paths (`choose_counter_kind.rs`), so without consumption a skipped or auto-resolved `Choose` would latch a stale answer. Hostile pinned in C1 (Spectral Shift with Entwine: two modes each latch their own answer).

## 7. Identity / Provenance Contract
- Phrase: "replacing all instances of one <word class> with another" on "target spell or permanent".
- Authority: the pair (from, to) the spell's controller selects from the NamedChoice prompt; type `TextSubstitution`; value fixed at answer time.
- Binding time: at resolution (CR 608.2d), latched when the `GenericEffect` installs its transient effect (`latch_chosen_text_words`, which consumes `last_named_choice`), after the prompt answer; the affected object is the target bound at install (CR 611.2c; `ParentTarget` → `SpecificObject`).
- Storage: `TransientContinuousEffect.modifications[SubstituteTextWord{Fixed}]` with the effect's `duration` and timestamp (CR 613.7b). Not stored on the spell object, which leaves the stack.
- Consumers: Layer-3 pre-pass (battlefield) and `restamp_resolving_spell_text` (stack spell). Both read the same transient list through the one `active_text_substitutions` authority; the incremental flush escalates to the full pass rather than consuming it.
- Live vs snapshot: words snapshotted; the recipient set snapshotted; the text is re-derived from printed text every layer pass (battlefield), so expiry reverts with no undo code.
- Invalidation: `Duration::UntilEndOfTurn` by `prune_end_of_turn_effects`; `Permanent` by `prune_affected_object_left_effects` (recipient leaves) — existing machinery.
- Multi-authority hostile fixtures: two text changes on one permanent in both timestamp orders (§9 P4); two different permanents each hit by a separate substitution (no crosstalk, P8); the same words chosen against a spell vs a permanent (S1 vs P1); two Entwine modes each latching their own answer (C1).
