## Blocking finding

### R3-1 [behavior] The proposed `depends_on` edge is recipient-blind, and the engine's cycle fallback is whole-bucket, so an unrelated object's text effects corrupt a chain
Plan (§3.3): "The edge is computed across all Text-layer effects regardless of recipient; a cross-recipient edge only reorders effects that touch different objects, and `active_text_substitutions` groups per recipient, so per-object order is exactly the CR 613.8 order restricted to that object's effects."
That claim is false given the existing implementation. `order_with_dependencies` (layers.rs 7817-7829) on ANY cycle returns the WHOLE bucket in timestamp order (its own comment: "coarser: on ANY cycle it reverts the WHOLE layer bucket"). The plan's `b.from == a.from` edge is symmetric, so two text effects with the same `from` on DIFFERENT objects form a 2-cycle (a loop, CR 613.8b). Concrete failure: Bog Wraith X carries chain A=`Swamp->Plains` (cast second) and B=`Plains->Forest` (cast first); on a separate permanent Y any two Hacks sharing a `from` (e.g. `Swamp->Plains` and `Swamp->Forest`, exactly the P8 pair). The Y pair forms a cycle, the whole Text bucket reverts to timestamp, X resolves B then A => Plainswalk, where CR 613.8a/b (the chain, which has no loop on X) requires Forestwalk. Two Hacks with the same `from` on two objects is ordinary play, so this is reachable, not theoretical. CR 613.8a dependency is also about applying the other effect changing "what it does to any of the things it applies to", which for a text effect is per recipient object; an effect on Y cannot change what an effect on X does.
Required revision: the `SubstituteTextWord` arm of `depends_on` must first require both effects' `affected_filter` to be the same `TargetFilter::SpecificObject(id)` (`ActiveContinuousEffect.affected_filter` is `tce.affected`, verified at the gather site), return false otherwise, then apply the domain/`to==from`/`from==from` rule. Correct §3.3's sentence accordingly (cross-recipient effects are independent, no edge). Add to P4 (and the `layers.rs` `depends_on` unit test) a third-object hostile: chain pair on Wraith X in the reverse casting order plus a same-`from` pair on Wraith Y in the same scenario => X still ends with Forestwalk (revert-fails: drop the same-recipient guard, X flips to Plainswalk); unit: `depends_on` false for same-`from` effects whose `affected_filter` are different `SpecificObject` ids. Also record in the claims ledger that the whole-bucket cycle fallback (layers.rs 7820-7828) was read and is why the guard is required.
