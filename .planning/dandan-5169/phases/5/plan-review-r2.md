### N2 [behavior] P4 and §3.3 apply text effects by timestamp alone; CR 613.8 is unaddressed
Plan: "orders them with `order_active_continuous_effects(Layer::Text, …)` (timestamp, CR 613.7/613.7b)"; P4: Hack `Swamp -> Plains` then `Plains -> Forest` => Forestwalk, "reverse casting order => Plainswalk".
CR 613.8a (grepped, line 3044): an effect depends on another when both are in the same layer and applying the other "would change the text or the existence of the first effect, what it applies to, or what it does to any of the things it applies to"; 613.8 "will override the timestamp system"; 613.8b: loops fall back to timestamp. Case analysis for the plan's own pair: E_a = `Plains -> Forest` depends on E_b = `Swamp -> Plains` (applying E_b creates the Plains word E_a acts on); E_b does not depend on E_a. So the dependency order is b then a => Forestwalk in BOTH casting orders, and the plan's reverse-order Plainswalk expectation is what the rules forbid. `Layer::Text.has_dependency_ordering()` is true (types/layers.rs:64-76), so `order_active_continuous_effects` runs `order_with_dependencies`, whose `depends_on` is shape-based (layers.rs 7873+) and has no arm for the new variant: it would silently fall back to timestamp. The charter's #1 hard rule is CR fidelity, and its Deferral list is "None".
Required revision: (a) state the 613.8a reading in §3.3; (b) add a `depends_on` arm in `game/layers.rs` for two `SubstituteTextWord{Fixed}` of one domain: a depends on b iff `b.to == a.from` (b creates a's word) or `b.from == a.from` (b consumes a's word; symmetric, so a loop, resolved by timestamp per 613.8b). The predicate reads only the modification payload, so it stays state-blind and invariant across the pass as `depends_on`'s own comment requires; (c) rewrite P4: chain pair (`Swamp->Plains`, `Plains->Forest`) => Forestwalk in both orders (revert-fails: drop the arm, the reverse order yields Plainswalk); loop pair (`Swamp->Plains`, `Swamp->Forest`) => timestamp order, Plainswalk vs Forestwalk by order; each assertion positive. If the executor instead concludes the engine's shape-based approximation should not gain the arm, that is a stop-and-return with the CR 613.8a text, not a silent timestamp result.
