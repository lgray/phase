## Decision revisions

### D1 — Best-of-three is a live Dandan path that no phase owns; the single deck pool dead-ends game 2
Charter coordinates: Phase 6 Goal "`state.deck_pools` holding one pool"; Phase 2 Goal (no match-type axis); no phase names `match_flow.rs`. `grep -n -i 'bo3\|match_flow\|between.games\|rematch\|sideboard' phase-charter` matches nothing relevant (the brief is silent too).

Measurements (all reads of HEAD code):
- `client/src/components/lobby/HostSetup.tsx` (`effectiveMatchType = playerCount === 2 ? matchType : "Bo1"`; the Bo3 button is disabled only by `playerCount !== 2`): Dandan is 2-player, so Bo3 is selectable for it with no format gate.
- The fixed-deck path skips deck validation (`crates/engine-wasm/src/lib.rs` `if !format_config.format.supplies_fixed_deck()` around line 1670), so the "BO3 requires a sideboard" refusal (`deck_validation.rs`, both `bo3_ready` checks) never runs for Momir or Dandan. Momir Bo3 works only because every seat has its own pool (`match_flow.rs` carries a Momir-specific comment at the restart).
- `match_flow.rs::handle_game_over_transition`: any 2-player Bo3 enters `BetweenGames`; `bo3_sideboard_players` is `[PlayerId(0), PlayerId(1)]`; `handle_submit_sideboard` returns `Err("Deck pool not found for player")` for the seat with no pool; the AI's `sideboard_actions` (`ai_support/candidates.rs`) returns no action without a pool (stall); `deck_payload_from_current_pools` returns `Err("Missing player 1 deck pool")`; and the restart rebuilds with `load_deck_into_state` (not `load_and_hydrate_decks`), so Phase 6's one-pile branch is bypassed even if pools existed.
- `match_flow.rs` is an `[architecture_scope]` pattern in `.agents/pr-review-policy.toml`.

So after game 1 of a Dandan Bo3 the match soft-locks, and a repaired restart would still deal each seat its own library. This is a whole-task need (the deliverable is a playable format) with no landing phase.

Required revision (decision): the charter must pick and phase-attribute one of (a) Dandan is best-of-one: an engine-owned typed refusal at the single authority that decides match structure, plus the lobby Bo3 control disabled from the engine answer (frontend displays, does not decide), or (b) the between-games rebuild is shared-zone aware (one pile through the Dandan provisioning, no per-seat sideboard prompt). It lands with Phase 6's deck provisioning (or Phase 2's axes for (a)) and adds `crates/engine/src/game/match_flow.rs` (and, for (a), the lobby/HostSetup path) to that phase's scope. New acceptance row, red at that phase's base: drive a Dandan Bo3 to the end of game 1 and assert the chosen behavior (for (a): the Bo3 config is refused with a typed reason; for (b): game 2 restarts with one 80-card pile and no seat-1 sideboard prompt), with the Momir Bo3 restart as the positive reach-guard that the instrument reaches `restart_between_games_with_starting_player`.

### D4 — Seat-keyed `deck_pools` readers: the AI's own deck analysis is owned by nobody

Measurement: `git grep -n 'deck_pools' -- crates/phase-ai/src ':!*test*'` at HEAD names, beyond `deck_knowledge.rs` (lines 29, 62, 164), `session.rs::AiSession::from_game` (builds `deck_profile`, `features`, `plan`, `strategy`, `synergy` only for pools present; its own doc: "Decks not present in `state.deck_pools` get default (empty) entries") and `search.rs::deck_color_demand` (returns `[0; 5]` when the seat has no pool). `build_ai_context_with_session` then reads `session.deck_profile.get(&player).cloned().unwrap_or_default()` and `session.strategy.get(&player)...unwrap_or_default()`; `deterministic_choice`'s mulligan branch consumes `features`/`plan` the same way. ### R1 — Phase 4 asserts that Hinder is the same class; its AST carries no `countered_spell_zone`
Old text (Phase 4 Goal): "(the brief also names Remand, Hinder, Spell Crumple and Lapse of Certainty as the same class)". Old text (Phase 4 Claims to establish, second bullet): "The class members named above are flipped by the same acceptance — buy by the same jq over those names (a member that stays unsupported for another reason is reported, not force-fixed)."

Measurement (`client/public/card-data.json`, `coverage-data.json`): Memory Lapse, Remand (`Hand`), Lapse of Certainty (`Library Top`) and Spell Crumple (`Library Bottom`) each parse to `Counter { countered_spell_zone: Some(_) }` and are flagged only `Swallow:Replacement_Instead`; Hinder parses to `Counter { target }` with no zone plus a `sub_ability` `ChangeZone { destination: Graveyard, target: ParentTarget }`. Replacement, Goal: "(the brief also names Remand, Hinder, Spell Crumple and Lapse of Certainty; this phase measures which of them are the same class — a member whose parsed `Effect::Counter` carries no `countered_spell_zone` is not one)".
Replacement, claim: "A named member flips exactly when its parsed `Effect::Counter` carries `countered_spell_zone: Some(_)` — buy by `jq` over each member's `.abilities[].effect` in `client/public/card-data.json` and the regenerated `coverage-data.json`; a member whose AST lacks the zone stays flagged, and that flag is left red."
Also add to the Verification plan's reach-guard: "Hinder (verbatim Oracle text, no zone in its AST) stays `Swallow:Replacement_Instead`." No decision moves.
