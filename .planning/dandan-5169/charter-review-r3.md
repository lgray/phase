## Decision revisions

### F1 — The ceiling as a stored `FormatConfig` field: wrong authority as specified, fail-open default, and none of the field's required machinery is chartered
Class: decision revision (Phase 2 Goal, scope rule and acceptance rows; Phase 7 Goal and claim 4).

Charter coordinates:
- Phase 2 Goal: "a typed best-of-three ceiling on `FormatConfig` (a value over the existing `MatchType`, never a `bool`: Bo3 for every existing format, Bo1 for Dandan, deserializing to Bo3 when absent; mirrored in the client's `FormatConfig` type and registry entries; it is not one of the five axes — it is the one lobby-facing fact Phase 7 needs and rides the config surface because the axes have no wire surface by design)".
- Phase 2 Verification: "a serialized `FormatConfig` without the field deserializes to Bo3 (revert-failing: drop the serde default ...)".
- Phase 7 Goal: "The ceiling rides `FormatConfig` because the format axes are engine-only by design (no wire surface) while the lobby needs the answer."

Measurements:
1. The brief (issue body, "Format predicates are axis methods on `GameFormat`, not stored `FormatConfig` fields") rejects a stored field and prices it: "a stored field would need a verdict row in `built_in_axes_no_looser_than_rules`, a `for_custom_rules` value, the client `format-config-shape.ts` guard plus rehydrate, 25 `formatRegistry.ts` edits, and an extra protocol bump". The charter adds exactly such a field and charters only the last two costs (registry entries, bump). Not chartered: the verdict row, the `for_custom_rules` value, `client/src/adapter/format-config-shape.ts` and `client/src/adapter/__tests__/format-config-shape.test.ts` (exists: `git ls-files | grep format-config-shape`; its own header says it requires "every field present" for blobs rehydrated from `localStorage` and broker `JoinTargetInfo`/`PeerInfo` frames, so a new field either breaks stale saved blobs or needs a migration).
2. `FormatConfig::deserialize` gates every untrusted config through `built_in_axes_no_looser_than_rules` (format.rs ~875; "checks every one of this struct's 18 fields", six verdicts) and, for Custom, exact equality with `for_custom_rules` (~1223-1260). Every existing fail-safe field uses the **bottom** element as its serde default (`default_sideboard_policy_fallback` = `Forbidden`, format.rs ~599-602, "the same class of hole as a forged `sideboard_policy`", ~426). The charter's default is the **top** element (Bo3). For Dandan, a payload that omits the field, or declares Bo3, decodes to ceiling Bo3, so the enforcement's only input is host-controlled: a modified host can request a Dandan Bo3 and soft-lock the opponent at game 1's end. The charter's own revert-failing test ("drop the serde default and the pre-existing payload fails to decode") tests only the legacy-format direction and never the Dandan direction.
3. The premise "the axes have no wire surface ... while the lobby needs the answer" is answered by an existing route: format-keyed axis answers already reach the pre-game client through wasm (`isCardCommanderEligibleForFormat(name, format)`, `engine-wasm/src/lib.rs` ~1106, used in `useDeckBuilder.ts`/`ImportDeckModal.tsx` before any game exists; `HostSetup.tsx` already awaits wasm for saved custom formats via `isResolvingFormat`). The engine enforcement needs no wire at all: `state.format_config.format` is already in the state, and `Custom(_)` returns the stock Bo3 answer per the axis convention.
4. Sizing consequence: keeping the field makes Phase 2 carry a second lockstep mechanic (field + verdict row + custom-rules value + shape guard/test + 25 registry mirrors) beside the format variant. Phase 2's T2 is already 19 named paths (5 tests excluded by T2 leaves ~14, still >= 13), and its T1 = 1 rests on the ceiling being folded in. With the field, T1 is arguably 2 and the conjunction fires; the "one unit" claim is not measured.

Required revision (decision): replace the stored field with a sixth typed axis method on `GameFormat` (a best-of-three ceiling, exhaustive match, `Custom(_)` = Bo3, joining the five in `format_axis_census.rs` so `format_axis_methods_carry_no_wildcard_arm` covers it), enforced in `start_game_with_starting_player` from `state.format_config.format`, with a wasm export beside `isCardCommanderEligibleForFormat` that the lobby awaits to disable Bo3 and submit Bo1 (registry helper in Phase 7 becomes that wasm call). Consequences to rewrite: Phase 2 "5 new typed predicate axis methods" -> 6, drop the ceiling clause from the `FormatConfig` sentence, drop the `FormatConfig::dandan()` ceiling assertion and the client-registry Bo1/Bo3 mirror rows and the "deserializes to Bo3 when absent" row (replace with: the axis returns Bo1 for Dandan and Bo3 for every other built-in and for `Custom(_)`, positive reach-guard that the method is read per format); Phase 7 claim 4 ("on the wire and in the client mirror") becomes "the ceiling is an engine axis reached by the lobby through the wasm export; no serialized shape changes" (`check-protocol-version.mjs` unaffected by it); Phase 7 scope gains `crates/engine-wasm/src/lib.rs` (the new export only) and loses the `formatRegistry.ts` helper; Phase 7's `HostSetup` row stays. If the planner instead keeps a stored field, the revision must add, with rows red at Phase 2's base: (a) a `built_in_axes_no_looser_than_rules` verdict row `NoLooserThan` (Bo1 < Bo3) so a Dandan payload declaring or defaulting to Bo3 is refused at deserialize (test: Dandan `FormatConfig` JSON without the field and with `Bo3` both fail), (b) the `for_custom_rules` value and the Custom-arm equality, (c) `format-config-shape.ts` and its test with the rehydrate policy for stale blobs, (d) a recount of Phase 2's T1/T2 with the ceiling counted as its own unit.
